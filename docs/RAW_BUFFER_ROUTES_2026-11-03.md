# 主 RAW 编码输入与 AF/PdAf 缓冲的区分

日期：2026-11-03，Asia/Shanghai。对象：初代 Nikon Z6 C3.80。接续[自动参数研究](RAW_AUTO_PARAMETERS_2026-11-03.md)，继续落实保留暗电流、关闭静态 NEF 写入前 RAW 校正、消除彩圈三个目标。

**本轮进展是定位数据路径，不是破解完成。** 原厂指令、调用与内存共同确认 `0x2006b3xx` 涉及 AF/PdAf 缓冲；另沿静态照片对象恢复了 RAW 编码请求的输入、输出和寄存器传递。六组隔离执行通过，但没有处理真实像素、生成有效 NEF 或关闭真机校正。

原始升级包及四个解包模块保留；QEMU 使用已有 Linux 副本，Unicorn 使用只读可执行的进程内固件映像。没有修改原固件、生成刷机包、刷写或提交 Git。本轮没有改动 QEMU 的像素算法或定时器模型。

## 1. 与最终目标的关系

| 问题 | 新证据及其等级 | 对下一步的影响 |
| --- | --- | --- |
| `0x29c` 是否就是暗电流开关？ | 原厂静态指令和 QEMU 原生调用证明：同一 `0x2006b3xx` 寄存器区的 bank 地址进入 AF 记录，并被 `PdAf` 导出代码读取 | 不能再单凭有符号四槽就称其为全局黑位或暗电流扣减；仍需证明它是否、如何影响主 RAW |

## 2. `0x2006b3xx` 与 AF/PdAf 的直接联系

证据不是两个名称“离得近”，而是相同的数据地址沿指针链传播。

原厂 `0x100d8594(bank, address)` 转到 `0x1010b9c6`：bank 为零时向 `0x2006b3c4` 写地址，否则向 `0x2006b3c8` 写地址。初始调用 `0x100bc690/0x100bc698` 为两 bank 提交队列元素 `+0xc` 中的地址；后续 `0x100bf734` 也通过该包装函数更新 bank。

同一段队列管理代码在 `0x100bf750` 把 AF 句柄写入帧对象 `+0x7c`。发布函数 `0x1018511e` 中的 `0x10185172..0x1018517a` 将该句柄的 **0x70 字节**复制到 AF 环形记录 `+0xc0`，因此句柄 `+0x6c` 的数据指针成为记录 `+0x12c`。记录区起点 `0xc2152370`、步长 `0xc30`、共八槽。

`0x1018551c` 返回选中记录。导出路径 `0x100a0e92..0x100a0eb4` 读取其 `+0x12c`，以长度 `0x22cc00` 和文件名模板 `A:\PdAf%03d.bin` 调用 `0x100a0dd4`。本轮没有主动调用导出函数、也没有产出这个文件；这一段是原厂反汇编证据。

第二次完整跟踪 `native-pdaf` 的发布内存中观察到：

| AF 句柄 | 句柄 +0x6c / 记录 +0x12c |
| --- | --- |
| `0xc2bde8b0` | `0x893bbc00` |
| `0xc2bde940` | `0x8965ee00` |
| `0xc2bde9d0` | `0x89902000` |

五次发布快照的 0x70 字节完整匹配。bank 0 的写入观察包括 `0x893bbc00 / 0x8965ee00`，bank 1 的初始写入为 `0x893bbc00`。这些地址出现在发布记录中；断点每个调用窗口只保留首次命中，**不把不同窗口的两条事件强行拼成同一帧**。

此外，原厂 `0x100bc450` 填写 `0xc25ee130`；`0x100d85a0 → 0x1010b9d6` 将其提交到 `0x2006b3c0..0x2006b3fc`：

| 参数结构偏移 | 地址寄存器 | 本轮模拟环境值 | 行步长寄存器和值 |
| --- | --- | --- | --- |
| +0x20 | `0x2006b3e8` | `0x8c8c3400` | `0x2006b3ec = 0x3000` |
| +0x2c | `0x2006b3f4` | `0x8cec6400` | `0x2006b3f8 = 0x2400` |
| +0x18 | `0x2006b3e0` | 既有稀疏列表地址；模式 3 本轮为 `0x8d41e400` | 本轮不赋予像素输入/输出语义 |

前两项由参数对象 +0xc8/+0xcc 的句柄，经句柄 +4 的地址向量得到。它们与 bank c4/c8 的地址不同，不能混为同一组像素缓冲。

**结论边界：**已确认这个寄存器区参与 AF/PdAf 数据路径；尚未证明全部 b3xx 功能只服务 AF，也没有证明原 `0x29c` 四槽对静态 NEF 毫无影响。保留此前“静态拍摄复用这些参数”的事实，同时降低“这就是主 RAW 黑位开关”的假设优先级。QEMU 当前未实现这组寄存器对应的真实像素处理，发布地址不等于有效相位像素。

## 3. 从原厂任务注册找到独立的 RAW 编码路径

任务表名称位于每个 0x1c 字节描述符的 **+0x10**。启动复制表与两张运行时元数据表核对如下：

| 名称 | 元数据 ID | 注册代码 / 工作函数 | 证据边界 |
| --- | --- | --- | --- |
| IMPRAW | `0x7a` | `0x101ca940` / `0x101ca864`，对象 `0xc1d88798` | 本轮继续追踪的 RAW 请求服务 |
| IMPRAWRS | `0x79` | `0x100d72ca` / `0x100d70fc`，对象 `0xc1d88910` | 独立服务，不能与 IMPRAW 合并 |
| PREPRO | `0x10038` | `0x100bcc5e` 注册片段 / `0x100bcb0a` | 与此前 b3xx 路径有关 |
| STGRAW | `0x10048` | 尚未恢复工作函数 | 只保留名称与元数据锚点，不称为已追通的 NEF 写入服务 |

表基址 `0xc18fd93c / 0xc18fe870` 来自原厂 getter 及第二、三次运行内存；第一版未抓取该字段。字符串和启动 ROM→RAM 映射另存于任务锚点（`analysis/raw-buffers-2026-11-03/task-anchors.json`，本地归档未公开）。

静态调用链：

```text
0x100af648：从请求 +0xc 取得拍摄对象
  输入 = *(拍摄对象 +0x1f8) +0x24
  输出 = *(拍摄对象 +0x330) +0x50
  → 0x100a323e：构造 RAW 请求包 0xc23234c8
  → 0x101caad8 → 0x101caa50 → 0x101caa3e：提交 0x42172c42 请求
  → IMPRAW 工作函数 0x101ca864
  → 0x101ca7f0 → 0x101ca6c6：字段转换
  → 0x10108f8a：寄存器打包
  → 0x101091e4 / 0x10108f6c：控制掩码与启动位
```

`0x100af648` 受原厂资格检查、输入指针和输出完成标志控制；不是无条件处理每张图。`0x100af596` 通过 `0x10125a30` 获取输出句柄并存入拍摄对象 +0x330。失败路径还可能调用 `0x100a3480`，尚未覆盖全部模式。

上述链条明确连接照片对象、RAW 任务和编解码硬件配置；**本轮没有追到最终 NEF 文件写入**，因此“主 RAW 编码路径”是按这些调用与布局作出的定位，不等于已经拿到完整无校正输出。另一个请求 `0x42172c41` 使用不同字段和调用者，可能属于资源/回放解码，不能把所有带 RAW 名称的路径统称为静态照片编码。

## 4. 六组隔离执行：验证地址传递，没有模拟像素算法

脚本：[probe_raw_io.py](../tools/fw/probe_raw_io.py)。执行未改动的 `0x100a323e`，**在进入排队函数 `0x101caad8` 前停止**；将其生成的请求包放入隔离上下文，再执行原厂 `0x101ca6c6` 和 `0x10108f8a`。

输入描述符中的 byte+0 为数值格式 ID，halfword+2 为字节行步长，+0xc/+0xe 为裁切起点，word+0x10 为像素基址。输出描述符 +2/+4 决定本次尺寸，+8 提供输出地址。

| 数值格式 ID | 裁切后的输入地址 | 输入步长 | 输出步长 |
| --- | --- | --- | --- |
| 2 | `0x60018012` | 12288 | 9008 |
| 3 | `0x60018018` | 12288 | 12000 |
| 4 | `0x60018015` | 12288 | 10512 |

每行分别执行输出模式 ID 1、2，共六组。人工输入基址 `0x60000000`、裁切起点 (12, 8)，输出 6000×4000、地址 `0x62000000`。行内偏移分别按 `floor(x×3/2)`、`2x`、`floor(x×7/4)` 计算。这支持相应打包布局的判断，但尚未绑定相机菜单模式名称。

| 请求包字段 | 转换后字段 | 最终 MMIO |
| --- | --- | --- |
| +0x40 输入地址 | +0x38 | `0x20204400` |
| +0x44 输入步长 | +0x3c | `0x20204404` |
| +0x48 输出地址 | +0x40 | `0x20204420` |
| +0x4c 输出步长 | +0x44 | `0x20204424` |
| +4 / +8 尺寸 | +6 / +8 | `0x2020404c / 0x20204050` |

三段结果逐字段匹配。像素输入、输出地址**未映射**，任何像素读写都不能成功；MMIO 地址只映射为该进程的普通 RAM。调用没有产生编码结果，也没有替换队列返回值伪造成功。

输出模式 1 的可选表指针为零；模式 2 分别选择 ROM `0x1152ad70`（格式 2）或 `0x1152af70`（格式 3、4）。驱动把 256 个半字各取低 14 位、两两打包，写到 `0x20204200..0x202043fc`。六组中的三组表上传均逐字匹配原 ROM。

这里确认的是一维表上传。尚未恢复完整编解码数学或真实像素输入输出，不能称其为消圈表，也不能仅凭关闭表上传宣称获得未经校正 RAW。数值模式与无损/有损菜单的对应尚待独立核实。

## 5. 实际拍摄对象与编码前处理线索

第三次 `native-main-raw` 跟踪在原厂下层静态提交 `0x10076a08` 捕获到主 RAW 句柄 `0xc2c35558`；拍摄对象 +0x1f8 指向它。其 +0x24 描述符包含：格式 ID 2，尺寸 6104×4222，字节行步长 9168，裁切起点 (0, 0)，数据地址 `0xa448e000`。最终快照中同一描述符保持一致。

这些是**固定模拟环境的元数据**。没有读取并验证整幅像素，不用其尺寸或地址宣称真机完整传感器读出。此时拍摄对象 +0x1fc、+0x318、+0x330 为零；第三次已设置的后续处理入口、编码入口及寄存器打包断点均未命中。它们在有限窗口未出现，不证明真机不会执行。

向上游进一步找到 `0x100ae33e`：

- 把拍摄对象 +0x1f8 的句柄存入处理请求 `0xc233525c+8`，并携带拍摄对象及处理参数。
- 条件成立时将 +0x1fc 放入请求 +0x1a8。
- 调用 `0x100b4c78(1, 请求)`；后者经 `0x100b5716` 构造参数，再转到 `0x100d67f4` 提交。
- 返回后，若请求 +0x1a8 非零，在 `0x100ae424..0x100ae428` 交换拍摄对象 +0x1f8/+0x1fc 两个句柄。

因此，只看最初 RAW 地址不足以说明编码吃到了哪份数据，必须核对处理后句柄是否被替换。此处是**主 RAW 上的处理提交候选**，尚未将每个分支认定为降噪、暗场扣减或空间增益，也没有证明本次模拟运行执行了它。

对 +0x1f8/+0x330 的 STR.W 搜索只作候选目录；有些命中实际是释放句柄后清零，例如 `0x100ab79c..0x100ab7a0`，不能算作像素生产。搜索还会漏掉 STRD、memcpy 和计算地址写入；`0x100ac3f8` 的 STRD 就是一个已看到的例子。同偏移也不意味着相同类型对象。

| native-pdaf | 53 条观察，补充 bank 写入和 AF 句柄赋值 |
| native-main-raw | 60 条观察，补充主 RAW 描述符及后续处理断点；这些后续断点未命中 |

三次 QEMU 均沿用 `419a1f2a91a1f2d3a0209027c29606475f7fe26f` 及既有辅助启动：0x29e=1、传感器参数指针回退、合成输入、设备状态与时间 fixture 等。无卡诊断调用改变进程内状态；不是完整真机按键或硬件协议模型。没有新增完成位注入。每个 call_fixture 对每个断点只取一次，三次均未达到 256 条重装阈值；仍存在窗口外及重复帧的观测缺口。

保留的错误与更正：

1. 命令 01 的十六进制 branch 参数缺少 0x 前缀，被参数解析器拒绝；命令 02 修正。这不是固件异常。
2. 命令 15 错把任务名称当成描述符起点，断言失败；按原厂 getter/注册代码确认 +0x10 后，命令 16 重新生成。这不是任务表损坏。
3. 第一版 native-buffers 把静态拍摄对象标为 frame，并按另一种帧布局读取 +0x78/+0x7c。这些读数不作为静态 RAW 缓冲结论；第二版区分对象，第三版补抓 +0x1f8/+0x330。
4. `curated-evidence-v2` 去掉任务 getter 后一个常量池半字，并补全启动寄存器片段；第一版保留，正式引用 v2。探索性线性反汇编可能包含常量池、跳转表或错误起点，不是完整函数证明。
5. 首次综合校验命令 35 假定第一版跟踪也含任务表基址快照，因缺少字段报 KeyError。已按各版实际观测范围修正；失败日志及当时校验脚本保留，不回填旧内存记录。

精选反汇编 v2（`analysis/raw-buffers-2026-11-03/curated-evidence-v2.txt`，本地归档未公开）包含 26 段指令；[校验脚本](../tools/fw/verify_raw_buffers.py)检查原始五文件哈希、脚本快照、内存摘要、AF 复制与地址对应、任务表映射、六组寄存器结果及文档链接。校验报告（`analysis/raw-buffers-2026-11-03/verification.json`，本地归档未公开）保存结果与材料哈希。校验不把模型像素效果列为已验证。

## 7. 下一步只沿最终目标推进

1. 从 `0x100ae33e → 0x100b4c78 → 0x100b5716 / 0x100d67f4` 恢复主 RAW 编码前处理清单：逐项跟踪参数来源、使能分支、硬件寄存器和缓冲读写。重点分别找黑位减法/下限裁切、位置/邻域替换、空间颜色增益。不能仅看参数名就定性。
2. 追踪 +0x1f8 初始生产及 +0x1fc 替换条件，将处理后描述符与 `0x100af648` 的输入逐字关联；区分 RAW 的几何裁切与导致暗信号丢失的数值裁切。
3. 继续从 +0x330 编码输出追到 NEF 写入；核实格式、位深、曲线与无损菜单关系。STGRAW 名称锚点只作为辅助，避免围着名字转。
4. 原 0x29c/0x29e 路径保留已验证结果；在证明主 RAW 像素联系之前，不作为默认的暗电流/消圈补丁候选。定时器模型仍为辅助任务。
5. 真机暗场、偏置、平场与可解码 NEF 的修改前后对照仍是最终验收。当前没有用户样本；没有因此伪造像素效果，也未缩减“关闭全部相关 RAW 校正”的目标。
