# modified4 实拍后的固定标定与前端 RAW 处理定位

日期：2026-11-09。目标仍为保留暗电流、关闭静态 NEF 写入前的 RAW 校正并消除彩圈。本轮使用原版及已交付 modified4 的只读代码，实验数据放在私有内存；没有生成或刷写新固件。

## 结论与本轮取舍

modified4 平场中的宽环没有整体减弱，因此没有把已有 bit11 修改继续当作消圈成果。本轮向更早的前端追踪，接通了两个不同标定入口的源字段、原生选择器、上传寄存器和归零条件：

| 路径 | 数据与控制来源 | 原厂归零条件 | 验证到哪一层 |
|---|---|---|---|
| ID35 定长数据 | CAL38 的字节控制；ID35 存储区提供数据 | 控制字节为 0，写 `2006103c=0`，选择器跳过上传 | 52 组源字段→寄存器、56 组指针／模式／门控；模型中的静态阶段实际到达 |
| ID0b 可变长度列表 | CAL38 记录半字、context+5a；ID0b 或显式输入指针提供列表 | context+84 非零或 context+5a=2，使 `20061250=0` | 18 组原厂参数构造和5次寄存器上传、8组列表入口；物理处理名称继续识别 |
| 33×4 标定表 | CAL38+47180 起的分组记录 | 尚未认定中性数值或硬件关闭字段 | 60组选择／上传、3处独立单值扰动；完整modified4构造中2对单值扰动只有1个目标寄存器变化 |

“归零条件”指该控制字段和上传门控的实际原生行为。上表并未把零写入自动解释成已关闭所有 RAW 校正，也未把 ID35 或 ID0b 命名为已找到的彩圈算法。下一版候选应从已定位的控制来源收窄，先识别数据作用，再只改一个变量；目前交付版本仍为 modified4，没有新增 modified5 可刷包。

## 1. 实拍约束保持不变

沿用[modified4 实拍报告](MODIFIED4_REAL_NEF_2026-11-09.md)的原始结果，本轮没有修改平场分析或重新拟合出“改善”：

- 4902、4904、4905 三张真实 NEF 独立解码一致，共 73,495,680 个码值零差异；中性暗角／空间参数仍在文件中。
- 与 modified3 比，R/G 宽径向起伏约 1.380→1.544、B/G 约 1.350→1.311 个百分点。没有一致的整体下降；用户确认机位／对焦可能移动，照明与构图变化混在比较中。
- 这些是 Viltrox 16/1.8、屏幕光源、1/8000 秒、单一信号档的平场。宽色场结构和细密量化环分别解释，不能把每一个宽环都指定为固件伪影。
- modified4 暗场补丁的三处代码仍与先前一致；本次用户没有新拍 dark，最后一次实机暗场回归通过的版本是 modified3。局部强暗信号保留与完整暗电流恢复分项记录。

## 2. 新接通的更早阶段：ID35 与 ID0b

### 2.1 数据来源不是同一个指针

原生初始化 `100f5912..100f5930` 分别安装三个资源：

| 资源 ID | 安装到 `c18fa954` | ROM 目录／存储描述符 | 存储源及长度 |
|---|---|---|---|
| 38 | +14；本轮模型值 c9700000 | 11f1606c；storage18=11f15a20 | 13e80000，目录长度168000 |
| 35 | +18；本轮模型值 c9868000 | 11f16018；storage15=11f1599c | 13420000，目录长度d8000 |
| 0b | +1c；现有模型夹具把它清零 | 11f15b80；storage0b=11f157e4 | 12a80000／12e60000 两个描述符源，目录长度25fff8 |

表中地址及长度均为十六进制。这些源地址位于主模块 `10020000..1201367a` 之外；真实存储内容及是否逐机身唯一未在本轮读取。CAL38 的存储链前轮已有证据，本轮将 ID35 的消费者和控制接到同一张图中。`14500000` 是先前分析中 c9700000 的地址别名换算结果，不是本表的 CAL38 存储源。

目录原字节与边界记录见资源清单（`analysis/raw-front-calibration-2026-11-09/resource-survey.json`，本地归档未公开）；原初始化与选择器见门控反汇编（`analysis/raw-front-calibration-2026-11-09/secondary-cal-gates.txt`，本地归档未公开）。

### 2.2 ID35：控制字节 → 2006103c → 定长上传

原厂调用链为：

```text
1011c750(kind=0, context)
  1011c64e 选择 mode / temporary 对应记录
  CAL38 + 540 + record_index*80 的第0字节
  1011c798 / 1011c79c → c29a3230+1c
  10110c08 → 100cd64a → 2006103c

1011c750(kind=1, context), context+84 != 0
  1011c3f4 先检查 c29a3230+1c
  0：返回0，不提交新描述符
  非0：检查 ID35 指针并按 mode 选数据
  101229b8 → 10110cba → 100cda34
  20061264 = 数据地址；20061268 = 上传字节数
```

式中 `540` 为十六进制偏移，`80` 为十进制记录步长。控制字段为 0 时，原生代码确实把 `2006103c` 写为 0；这与只跳过后续上传、让旧控制寄存器继续保留，是两种不同操作。

模式与定长数据的原生映射已实际执行核对：

| mode | ID35 相对偏移（hex） | 字节数（decimal） |
|---|---|---:|
| 0、2、3 | a6e90 | 24416 |
| 1、4、12 | acdf0 | 24416 |
| 5 | b2d50 | 24416 |
| 6 | b8cb0 | 15904 |
| 7 | bcad0 | 24416 |
| 8 | c2a30 | 8160 |
| 9 | c4a10 | 15904 |
| 10、11 | c8830 | 8160 |

24416=6104×4，15904=3976×4，8160=2040×4。与 RAW 行宽一致的数量关系值得优先追；它只支持“可能按列／按宽度组织”的假设，数据也可能是索引或其他前端参数，尚未恢复其数值意义。没有把这组表盲目改成全零或全一。

56组入口测试包括 mode0..13、门控0/1、源指针有／无。关闭或无效路径不写新描述符，旧 `20061264/268` 保留；返回码分别按原厂代码检查。52组源字段测试覆盖13种mode、临时／普通状态、源字段0/1，确认目标寄存器确实覆盖旧值，邻近字段仍按原记录上传。

### 2.3 ID0b：另一条列表路径与显式策略值2

`1011c750(kind=1)` 从 `CAL38+e50+record_index*80` 取记录，调用 `1011c53c` 构造参数：

```text
context+84 != 0  或  byte(context+5a) == 2
    → c29a32b4+24 = 0
否则
    → c29a32b4+24 = u16(记录+32)

10110cb0 → 100cda0a → 20061250
```

上述偏移为十六进制，记录步长80为十进制。18组测试使用非零旧缓存和源半字0／1／17，验证策略0、1继承标定，策略2强制覆盖为0；临时状态也强制覆盖为0。临时状态清零不是整个静态拍摄都关闭，必须继续检查恢复顺序。

context+84=0 时调用 `1011c2a0`：门控非零后，优先使用 context+50 显式指针与 +54 数量，否则从 ID0b 选列表；最终共享 `20061264/268` 描述符。8组显式指针／长度测试验证选择、16字节对齐和空指针返回。此路径的部分静态结构早在[11月2日列表报告](LIST_PATH_2026-11-02.md)出现，本轮新增的是与定长 ID35 的区分、源字段归零条件和原生执行检查。

这两个门控虽然共用上传描述符，分别写入不同控制寄存器；后续实验必须拆开。

### 2.4 静态调用跟踪实际看到了什么

对确切 modified4 文件运行现有 shooting／no-lens／零标定夹具，新增只读观察点。第二次成功记录28个事件；静态窗口的顺序为：

```text
RAW destination ready (a448e000)
kind0 → CAL字段写入 → 全局驱动 → 2006103c写入后
kind1 → ID35选择器 → 20061250参数驱动
1017d7b6 静态前端构造 → 临时阶段退出 → kind2
```

其中 context.mode=1，context+84=1，kind0记录下标2，控制源为 `CAL38+5e0`，数据选择应为 `ID35+acdf0`。当前模型的该标定字节为0，故实际观察到选择器入口，未观察到本次定长描述符提交。本轮成功的两个跟踪分别为45和28个事件，全部未触及256事件截断上限。

模型保留既有合成初始化及硬件简化；没有新增像素算子、伪造中断或强制保存完成。ID0b 指针被旧夹具清零也已在记录中单列。两个成功跟踪的原始数据见表路径（`analysis/raw-front-calibration-2026-11-09/native-calibration-watch/result.json`，本地归档未公开）、更早前端路径（`analysis/raw-front-calibration-2026-11-09/native-secondary-watch-v2/result.json`，本地归档未公开）。

## 3. 33×4 与2×48表：从来源连到完整 modified4 上传

### 3.1 33×4：现在能精确追到每一个被改的表项

```text
CAL38 + 47180 + group*600 + category*300
  1011e2ce → 1011e23e（复制300字节记录）
  数据 c29a3be0，共33×4个u16
  控制 c29a372c / c29a3744
  packet c29a34c0 的 +50 / +2c / +30
  100bccd0 → 100d830a → 1010b3a8
  数据bank：20068f00 / 20068f44 / 20068fcc / 20068f88
```

CAL偏移十六进制，乘数600、300均为十进制。四路是存储顺序，尚未映射为 R、G1、G2、B。每bank写16个双项字和最后第33项，共68次表写入，另有13次控制写入。

group由mode、context+84和子模式选择；category比较的是 `1011da0e` 算出的有理量，不能直接把分界命名为 ISO。测试以非零CAL、num1535/1536、den192跨过8倍分界，覆盖60组组合。

3处独立扰动（源值+7）对应：

| 表项 | 唯一变化的寄存器 |
|---|---|
| index0、存储路0 | 20068f00 低半字 |
| index7、存储路2 | 20068fd8 高半字 |
| index32、存储路3 | 20068fc8 低半字 |

进一步直接运行交付 modified4 的完整 `1017d7b6` 构造，停在硬件调度前，再执行原厂上传。临时／普通状态各一对基线与扰动，4次均产生507次前端写入；两对中只有 `20068fd8` 高半字增加7，其他寄存器、报文、context和CAL保持比较预期。该结果验证真实固件指令的数据流，没有编写替代校正算法。

### 3.2 两项易误判已经排除

- `20068708` 的源字段在 context+dc 非零时为1，其他条件下会随保留状态交替1／0。它不能直接当作“一直关闭”的开关。
- 空 packet 跳过上传时，原有硬件寄存器数值保留。跳过表上传不等于清除或中性化旧表。

### 3.3 2×48缓冲并非每次都被完整更新

`CAL38+47010+group*32+category*16 → 1011e150 → 1011e20c → c29a3664 → packet+28 → 1010b166`。两组48个u16最终写入 `2006861c / 2006867c`，另外写 `200686dc/e0`。

在本轮选择器中，只更新每组前两个u16，共4/96项；92项保留旧缓存。用0xa55a预填非零缓存验证这一点。它们是当前函数的数据保留事实，不能推论真机92项恒为0，也不能把这个缓冲强称为完整空间增益曲线。

记录见60组与扰动（`analysis/raw-front-calibration-2026-11-09/extra-table-probe-v3/result.json`，本地归档未公开）、完整modified4构造（`analysis/raw-front-calibration-2026-11-09/modified4-builder/result.json`，本地归档未公开）、134组前端门控（`analysis/raw-front-calibration-2026-11-09/secondary-gate-probe/result.json`，本地归档未公开）。

## 4. 怎样从本轮结果收敛到下一版

1. 优先沿已见静态路径的 `CAL38+5e0 → 2006103c` 识别 ID35 数据用途；同时检查正常模式复用和后续重写。比较真实数据／其他生产者与当前平场的空间特征，确认它属于列级处理、坏点索引还是增益操作。
2. 对 `context+5a=2 → 20061250=0`，先补请求生产者和静态输入收窄点，再判断是否与曝光相关列表／坏点处理对应。现有暗场成果独立保留，不合并多个开关试错。
3. 33×4表已有逐值到硬件上传证据，下一项是寄存器功能和真正中性条件；不猜测0、1024、32768哪个是单位增益。
4. 只有选定单一控制变量后才制作下一份副本，再做 ABI、非零标定、模式切换、启动取景、NEF保存和升级／回退审查。真正消圈仍以固定布置、多信号级的真实NEF对照验收。

因此本轮产物是已执行验证的控制定位、可复现探针和下一候选的明确条件，不是新的刷机包。候选状态清单（`analysis/raw-front-calibration-2026-11-09/candidate-status.json`，本地归档未公开）可供下一轮直接接续。

## 5. 文件保护、复现和失败记录

原版包、解包主模块以及modified1–4的哈希分别校验；21个既有NEF源文件保持。此前modified4实拍84项、modified3实拍94项和modified4安装前233项冻结证据复核。详见验证结果（`analysis/raw-front-calibration-2026-11-09/verification.json`，本地归档未公开）。原始固件与已验证暗场补丁没有被编辑；没有Git提交。

每次执行的argv、时间、返回码、stdout、stderr位于命令目录（`analysis/raw-front-calibration-2026-11-09/commands`，本地归档未公开）。主要复现入口：

```powershell
.\work\re_env\Scripts\python.exe tools/fw/probe_front_extra_tables.py --output <新的证据目录>
.\work\re_env\Scripts\python.exe tools/fw/probe_modified4_front_tables.py --output <新的证据目录>
.\work\re_env\Scripts\python.exe tools/fw/probe_secondary_calibration.py --output <新的证据目录>
```

QEMU复现使用22号命令的完整WSL参数，替换输出目录即可；需要已安装的固定模型环境，默认先进行合成初始化。探针输出均拒绝覆盖已存在目录。

三次开发失败保留而不计通过：07号测试对交替字段的预期地址错写为2006870c，实际为20068708；08号测试参考分支遗漏mode2直接默认入口，原指令没有失败；20号QEMU探针尝试捕获MMIO区域，被只读RAM范围断言拦下。修正分别只涉及探针／测试参考；09号和22号成功输出另存新目录。20号没有放宽断言读取整个MMIO，改为捕获参数RAM并在驱动写后观察寄存器参数。
