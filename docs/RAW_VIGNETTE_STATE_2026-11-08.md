# 2026-11-08 接续：无电子镜头状态、静态曲线重放与排查取舍

本轮把上一轮找到的暗角支线放回现有无电子镜头测试环境核对：**原厂生成器输出两张常数 1024 的曲线，静态照片对象也带着中性标志和零强度；使用该对象副本重放静态生成器，结果相同。** 这使普通暗角支线在“望远镜拍摄仍有固定彩圈”的排查中降低优先级，下一轮主线转向机身固定标定与前端处理，同时保留四路负偏移、`0x720` 和 RAW 写回位置的研究。

另外厘清了两个容易误用的控制：主属性 `+7d=2/3` 来自拍摄对象的特殊数值模式；配置 `0x3e3=1` 在一组条件下会**解除**暗角中性化。两者均不作为通用关闭校正开关。

本轮证据包括三次 QEMU 会话、六组原厂选择器对照、九组／十三段隔离执行，以及 17 段、731 条精选原指令。QEMU 会话是逐步增加观察点的迭代，不算三台机身或独立拍摄样本。完整证据见摘要（`analysis/raw-vignette-state-2026-11-08/evidence-summary.json`，本地归档未公开）、校验（`analysis/raw-vignette-state-2026-11-08/verification.json`，本地归档未公开）、命令（`analysis/raw-vignette-state-2026-11-08/commands`，本地归档未公开）。前轮表上传和 NEFInfo 0006 的证据保留在[暗角控制报告](RAW_CONTROLS_2026-11-08.md)。

## 1. 本轮直接观察到什么

环境继续使用固定 Z6 QEMU、原版 C3.80 映像、`exmcu_no_lens=True`、已有合成取景／输入与时间夹具，以及诊断用 CaptureWithoutCard。未修改模型的校正算法或新增完成事件。以下“无电子镜头”指这个模型设置；真实机身条件仍需独立对应。

| 会话 | 记录数 | 观察重点 |
| --- | --- | --- |
| `native-no-lens` | 16 | 五次曲线入口／返回，静态对象及资源快照 |
| `native-selector` | 57 | 六次曲线返回，选择器原厂 getter 结果和静态标志赋值 |
| `native-comparisons` | 77 | 其中 41 条为原状态观察，36 条属于明确标记的人工属性对照 |

所有原状态下捕获的曲线返回均来自 `100c1fba → 1017235a` 这条取景相关路径。生成器属性 `+62=0、+63=1、+52=0`，输出两张 257 项 u16 表均为 1024，20 字节系数结构全零。入口和返回断点每个诊断调用只取一次，不把它们强行配对为同一次函数调用。

静态照片对象在前端提交处得到完整 0x3000 字节 owner 快照。三次会话均为：

```text
owner[0]       = 0
owner+25e      = 0       暗角强度输入
owner+25f      = 1       非缓存路径的中性标志
owner+227c     = 0       来源类型；其 128 字节区域全零
owner+358     ..+377     缓存区全零
owner+1014    ..+1027    系数结构全零
```

第二次会话明确命中 `1013fa5a`：即将写入 `owner+25f` 的 `r0=1`，该 owner 地址与随后静态提交快照一致。前端提交已发生；本窗口的静态曲线生成、后端 RAW 处理和编码入口仍未执行，静态属性全局区也保持零。因此下面的静态生成结果明确归为**快照驱动的隔离重放**。

## 2. 中性标志的真实生产者

完整选择器为 `1013c392`。它读取属性 `138d、1c14`、配置 `3e3`，并调用 `101496a8、1014962c` 等辅助判断。原状态观察记录了 getter 的实际返回：

| 观察点 | 返回值 |
| --- | --- |
| 属性 138d | 0 |
| 属性 1c14 | 0 |
| 配置 3e3 | 0 |
| 辅助判断 101496a8 | 1 |
| 辅助判断 1014962c | 1 |
| 选择器中性结果 | 1 |

原指令中，`1c14=0` 直接让 `1014962c` 返回 1；`101496a8` 在观测到的组合下也返回 1。选择器据此到达中性分支。该联系承接此前的来源状态研究，但本轮仍只赋予这些属性已验证的数值关系。

静态生产块 `1013fa50..1013fa68` 将选择器结果写入 `owner+25f`；结果为 1 时把 `owner+25e` 清零。取景相关生产块 `1013c5ae..1013c5be` 使用同一选择器，写状态对象 `+533`，同时清零 `+532`。因此中性标志与零强度有明确的原厂生产关系。

## 3. 用静态对象副本完整重放生成器

脚本加载第二次 QEMU 会话的 frame、owner、主 RAW 描述符和 `frame+270` 附属资源，保持其指针与内容。私有请求分别令缓存字节为 0／1，其他全局内存使用零初始化加 ROM 启动数据副本；这两种缓存选择属于测试输入，不冒称 QEMU 后端已执行。

每组完整运行：

1. `100c29c6`：原厂静态属性构造及 257 项曲线生成。
2. `100c24f2`：使用同一 owner 构造主处理属性，尺寸取自已观察到的主 RAW 描述符。
3. `101a0828`：由构造出的主属性生成该支线控制参数。

两组结果均为两张中性表、零系数／强度；主属性 `+7d=0`、`A+2b4=1`、计算上下文 `+604=0`。结合前轮已验证的驱动关系，**曲线本身中性时，主通路控制仍可为开启值**。不能只凭一个使能字节判断当前参数是否实施了非中性校正。

原始 ROM 只读／可执行映射，所有可写数据位于进程私有 RAM；此次重放没有映射像素载荷或硬件 MMIO。有效结果见validated-replay（`analysis/raw-vignette-state-2026-11-08/validated-replay/result.json`，本地归档未公开）。

## 4. 上轮 +7d=2/3 分支的上游条件

非缓存主构造器在 `100c26c2` 调用 `100c22e0(frame)`，于 `100c26c8` 写到主属性 `+7d`；这里 r4 已加 0x4f，实际偏移为 `0x4f+0x2e=0x7d`。缓存分支在 `100c2540` 将该属性清零。

`100c22e0` 的数值关系经七组独立执行核对。共同前提是 `owner+88=0、owner+98=0`：

| owner[0] | owner+1b0e | 返回主模式 |
| --- | --- | --- |
| 本次实际值 0 | 本次实际值 0 | 0 |
| 6 | 0 | 6 |
| 6 | 1 | 3 |
| 6 | 2 | 2 |

另验证 `owner+88` 非零优先返回 1、`owner+98` 非零返回 4，以及 `owner[0]=3、owner+1a1=2` 返回 8。模式 2／3 因此有明确的特殊对象条件，尚不命名为某个用户菜单；不能通过任意改全局拍摄模式关闭整条 RAW 校正链。

## 5. 0x3e3 的方向：某些条件下解除中性化

在第三次 QEMU 会话原状态记录结束后，通过原厂属性存储函数设置私有客体中的测试值，完整运行原厂 getter、两个辅助判断和选择器。五项属性及配置在结束后恢复并读回核对。没有替换函数返回值或修改固件指令。

共同人工属性为 `138d=1、1325=4、1c1d=1、1c21=1`：

| 1c14 | 3e3 | 两个辅助判断 | 最终中性标志 |
| --- | --- | --- | --- |
| 0 | 0／1 | 均为 1 | 1／1 |
| 2 | 0／1 | 均为 1 | 1／1 |
| 3 | 0／1 | 均为 0 | **1／0** |

最后一组说明将 `3e3` 置 1 可以解除当前暗角中性限制，而不是统一“关闭暗角”。这是这组属性的原厂控制流对照，未把人工组合命名为具体镜头、转接环或拍摄模式。详细调用及恢复记录见native-comparisons（`analysis/raw-vignette-state-2026-11-08/native-comparisons/result.json`，本地归档未公开）。

## 7. 对最终目标的实际取舍

- **彩圈：** 普通 257 项暗角曲线已有明确的中性条件，当前无电子镜头模型与快照重放均为中性；下调其作为固定彩圈根因的优先级。机身固定校正仍单独追踪，旧两组 17 项表保留独立来源与控制记录。旧来源区域本轮为零，下一步应查真实标定／来源及其他处理，而非再次人为填零宣布关闭。
- **暗电流：** `0x3e1 → 前端正参数／四路负偏移／0x720／BlackLevel` 的既有证据保持有效。本轮未新增暗场样本；当前模型 owner 的四个标量为零，因此不做重复的零值像素比较。下一步优先查逐机标定加载、前端运算与 RAW 取样位置，区分必要偏置、扣减与钳位。
- **保存像素：** 继续以同一静态请求的有效输入、处理写回和 NEF 编码输入为验收链。参数中性、元数据变化、软件事件和模拟器合成图各有各的用途；最终目标仍是实际保存样本保留暗信号并消除彩圈。

本轮结论是**排查范围更集中，并排除了两种容易走错的控制方式**。真实传感器／ISP 像素效果属于后续验收，当前成果不标为真机破解。
