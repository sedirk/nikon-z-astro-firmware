## 新增已验证结果

### 1. 启动内存初始化表已经得到代码支持

在固定 EG 中，Thumb 启动例程 `0x10020038` 从 `0x10020064` 的两个相对值恢复表范围 `0x10034000 .. 0x10034120`，每条 16 字节，共 18 条。三个记录调用 `0x1002006c` 做内存复制，十五个记录调用 `0x10020088` 清零。处理函数已反汇编核对。因此另一台电脑扫描得到的三段候选实际是同一张初始化表的片段。

这恢复了静态镜像到初始化 RAM 的映射，不等于完整启动、硬件初始化或运行时标定已经恢复。完整记录在 `analysis/local-2026-11-02/config_probe.json`。

### 2. “加载校正设置／选择空校正表”实际先经过通用配置字节接口

| 地址 | 当前确认的指令行为 | 限制 |
| --- | --- | --- |
| `0x101cb734` | 读取配置缓冲区中的一个字节；首次读取有初始化分支，索引 0 和 0x14 有特殊处理 | 名称“加载校正设置”来自模拟器标签，不是固件函数符号 |
| `0x101cb766` | 普通索引时写入 `uint8`，然后向通道 8 的回调列表分发标识 `0x043e0011` | 不是直接操作全部 RAW 校正算法 |
| 配置基址 `0xc20aa7c8` | 索引 `0x29e` 对应 `0xc20aaa66`，`0x3dc`/`0x3dd` 对应其他字节 | 配置字节不是一张标定表本身 |

本机执行未修改的上述函数，分别对三个索引完成读 0、写 1、再读 1。隔离环境显式把初始化标志设为 1，回调列表保持零初始化，不执行存储加载和 RTOS 注册，因此没有证明真实初始化后默认值、通知副作用或持久保存行为。

在没有注册回调的隔离环境中，写函数返回 `0x043e0011`，与交接日志中的值一致。源码显示它先作为通知参数使用，不能仅凭这个返回值把它当成错误码。

### 3. 找到 `0x29e` 的两处直接消费者，其中一处会构造带终止标记的空列表

固定固件的直接分支扫描加上下文反汇编确认：

- `0x100bc154`：所在函数从 `0x100bc118` 开始。读取 `0x29e` 后，值为 1 时转到 `0x100bc18e`。
- `0x100bc5b0`：读取同一字节，值为 1 时跳到 `0x100bc5d6`，影响后续结构体 `+0x18` 字段的选择。此路径尚未完整执行或连接到 NEF。

在第一个消费者的分支入口设置合成寄存器与独立 RAM 缓冲，执行原始指令，不修改固件代码：

| 配置值 | 本次执行范围 | 观察结果 |
| --- | --- | --- |
| 0 | `0x100bc150 → 0x100bc164` | 清零 `0x18f000` 字节，即 1,634,304 字节；停在正常表输入处理开始前 |
| 1 | `0x100bc150 → 0x100bc204` | 清零前 `0x39000` 字节（233,472 字节），每 `0x200` 字节写一个 `0xffffffff`，共 456 个标记；其余六个同尺寸区块保持合成哨兵值 |

两个实验均核对了清零边界之后的保护字节。正常分支的后续转换例程 `0x100bfb54`、`0x100bc0e4` 将 `0xffffffff` 用作条目终止条件。这为上游“空表”标签提供了实际代码依据；当前确认的是按块组织、带终止标记的列表结构。列表的物理用途、与坏点/相位像素/颜色校正的关系、是否进入完整静态 RAW 路径，都没有确认。

本次执行绕过了原函数的分配/锁定前序，从明确的中间基本块开始；没有真实源表输入，未运行通知回调、缓存/解锁尾部、传感器或图像硬件。这不是原厂完整拍摄流程，也不是可刷补丁。

### 4. “缺省校准分支”调用本身只是写入一个 32 位状态字段

`0x10122852` 的原始指令是把 R0 写到 `0xc18fa954 + 0x1c = 0xc18fa970`，再返回。没有在该函数中解析或分配校准表。用 `0x12345678` 和 0 两个输入执行原始函数，均观察到对应字段变化。

返回时 R1 恰好保留结构体基址 `0xc18fa954`，不足以证明它是一个有语义的返回表指针；R0 也保留输入值。下一步应追踪该字段的读取者，而不是先把 R1 指向的内存叫作“校准表”。另发现 `0x1017d6a4` 是通向该函数的包装跳转。
