# 两组空间表的原厂数据来源、缓存与状态条件

日期：2026-11-03，Asia/Shanghai。初代 Nikon Z6 C3.80。接续[候选处理与 NEF 像素证据](RAW_PIXEL_STAGE_2026-11-03.md)。目标不变：保留暗电流、关闭静态 NEF 写入前的 RAW 校正、消除彩圈。

同日后续：[系数接收写入与 RAW 完成、写回位置](RAW_WRITERS_2026-11-03.md)定位 slot15/17 的接收 DMA 配置与成功发布者，找到原厂缩放 12/20 初始化和状态设置函数；新增 23 组有效对照。本文保留前轮记录；真实物理来源和最终保存像素仍未验证。

**本轮把两组 17 项空间表向上追到了浮点系数输入、原厂转换、五槽缓存和状态发布链；仍未证明它们改变最终保存的 NEF 像素。** `0x1c14` 的一个原厂写入来源已经查明：它由上游状态映射而来，不是已经确认的“关闭 RAW 校正”开关。相关代码使用 `LensInfo.c` 诊断文件名，但尚未证明这份数据实际来自镜头通信，也没有把它定名为彩圈、色差、暗角或衍射校正。

最新版 14 组用例、73 个原厂函数／有界片段通过。使用只读 ROM 映像和私有 RAM，未修改原固件指令、未新增像素模型、未运行 QEMU 或刷机；没有生成 NEF 或提交 Git。原始升级包、四个解包模块和既有 QEMU 源码的校验见验证记录（`analysis/raw-spatial-source-2026-11-03/verification.json`，本地归档未公开）。

## 2. 已恢复的数据流

以下地址均属于此版本；`S = 0xc18d4090`。slot 是原厂缓冲描述符的数字索引，不是图像通道名。

```text
slot 15 或 slot 17 的当前缓冲
  +1：头字节；+2：八字节选择节点；+0a：864 个 float32
       │ 1015e0a0，条件 S+6 == 1
       │ 1015e05e，使用 S+0c 指定的二进制缩放
       ▼
c2802f7c + index * 0xda0，index 取自 S+0e，五槽轮换
  +0：头字节；+4：八字节节点；+10：864 个有符号整数
       │ 101c2660 → 10161264，作为四指针结果的第 4 项
       ▼
10072714：构造输入，+54 指向缓存数据 +10
  → 100c0eda：复制到 properties+40
  → 10196fe4 → 10197500 → 10197410（普通、非缓存捷径）
  → 选取系数网格并求六个系数 → 1019702a：生成两组 17 项表
  → 101975be：输出空间表；10197678：导出同源六系数

此前已连接：空间表 → bank+1200/+1224
            同源六系数 → NEFInfo 0x0007
仍未连接：这些硬件参数 → 实际保存 RAW 样本的改变
```

输入缓冲选择由 `100c3648(slot)` 完成：在 `c18db630 + slot*24` 描述符中，按 `c2813140[slot*4] & 1` 选择 `+0c/+10` 指针。本轮使用原厂启动复制表初始化描述符，没有用假函数返回值替代 getter。

### 普通与替代来源

`1015e0a0` 读取两项属性，**两项均等于 1** 时用 slot 17，否则用 slot 15：

| 属性 | 已恢复的读取来源 |
| --- | --- |
| `0x1045` | `10078046` 读取当前 slot 0 的 `+19/+1a` 两字节；分派器归一化为 0/1 |
| `0x303e` | 当前 slot 7 的 `+ae` 最低位；`10079ab2` 读取快照，另有当前缓冲 getter `10079abe` |

此处“替代”只描述程序分支，不代表已经确认增距镜、转接环或特定镜头类型。两个缓冲的原始描述符长度均为 `0xd8c`；其头字段标识也不能与同数值的全局属性 ID 混为一谈。

`1015e05e` 按 IEEE-754 位布局提取符号、指数和尾数，再移位为整数。本轮使用正常有限值、零和人工缩放值 20，例如 `16 / 2^20 → 16`、`32 / 2^20 → 32`；没有验证 NaN、非正规数、溢出或极端移位。缩放字段还有原厂设置入口 `101c1e58 → 1016129a`，后者将输入两字节存到 `S+0b/+0c`。**没有证明真机在此处总使用 20。**

缓存每次先前进一槽，索引达到 5 则回到 0；即使 `S+6 != 1`，也会清空新槽并推进索引。另一份相邻缓存由 `1015e134` 管理，基址 `c27fafc0`、槽跨度 `0x198c`，来源为 slot 14/16、系数字节数 `0x1950`。这是另一份数据，不能当作本轮两组 17 项表的第二来源重复计数。

### provider 的独立限制

`101c2660` 通过 `1015c32e` 读取 `S+3` 和 `S+6`；当 **`S+3 == 2`** 时清零四个输出指针、返回 0。其他分支通过 `10161264` 导出四指针，其中第 4 项为上述当前系数缓存。

`S+3` 与 `S+6` 是不同字段。不能将“provider 清指针”“停止填系数”和“关闭像素校正”画等号。本轮只单独验证空指针分支，没有将它强行接到要求有效指针的类型 1 构造器。

## 3. 0x1c14 来自状态发布，而不是已经确认的菜单开关

原厂 `1015e970(output_id_ptr)` 比较 `S+18` 的旧状态与 `S+6`：相等则返回 0，不发布；不相等则更新旧状态，并向 `10164b5c` 传入以下 ID／值：

| `S+6` | 属性 ID | 请求写入值 |
| --- | --- | --- |
| 1、2、3 | `0x1c14` | 对应的 1、2、3 |
| 0 或其他值 | `0x1c14` | 0 |

发布包装层路径为 `10164b5c → 10164b24 → 101706ae → 10170620 → 10070366`，其中还含锁和通知操作。属性组／描述符位于 `114dd788 / 114daf58`，值地址为 `c24cd198`，类型 7、长度 4。原厂 getter 的描述符查找也指向这个位置。

**实验边界：** 五个映射用例执行发布者前缀，停在 `10164b5c` 入口；检查参数后，另行进入完整 `10070366` 值存储函数，再用原厂 getter 读回。这证明映射与存储连接，但没有运行 OS 包装层，不能称为一次连续、完整的发布事务。另一个用例完整执行“状态未变”分支，确认不调用发布包装层。

对数值状态 0、2、3，另做属性值与 `S+6` 一致的输入构造用例：

- 类型 0、2：`10072714` 走清空主体的回退分支；空间属性区清零。
- 类型 3：走另一套输入构造；`100c0eda` 将普通空间数据有效字节置 0、数据指针清零，同时将另一字节 `properties+48` 置 1。
- 三组人工输入下，普通六系数和两组表均为零。这只说明该分支和夹具的输出，**不能据此断言无镜头、转接镜头或望远镜拍摄没有校正**。

`LensInfo.c` 关联并非仅凭邻近字符串猜测：`10163d76` 的 PC 相对寻址把 `10163d5c` 的文件名字串传给属性接口；`1015c2b2` 等初始化代码也将 `1015c370` 的同名字串作为诊断参数。它支持“LensInfo 关联路径”的描述，仍不足以给具体校正算法或通信协议命名。

## 4. 原厂代码实验与观测陷阱

脚本：[probe_spatial_source.py](../tools/fw/probe_spatial_source.py)。最新版结果：`analysis/raw-spatial-source-2026-11-03/isolated-source-v7/result.json`（本地归档，未公开）。

ROM 映射为只读、可执行；全局区从原厂启动表复制两段初始化数据，其余私有 RAM 清零。人工源数据包含 8 个节点 × 6 组系数 × 18 项基底，共 864 个 float32；每组只给常数项非零值。节点字节为 1–8，选择量为 0。输入不是镜头通信抓包、机身标定或真实 RAW。

| 用例 | 已验证结果 |
| --- | --- |
| ordinary | slot 15 输入经转换、缓存、普通生成器得到 `[16,0,0,32,0,0]`，两表分别为 17 个 1、17 个 2 |
| alternate | 两项条件均为 1，选 slot 17；输入是普通来源的三倍，得到 `[48,0,0,96,0,0]`，两表为 3、6 |
| wrap | 旧索引 4 回到 0，数据与 ordinary 相同 |
| source-inactive | `S+6=0` 时不读取浮点数据，缓存及两表为零；此用例故意仍令 `0x1c14=1`，仅隔离生产者依赖，不模拟真实无镜头状态 |
| provider-type2 | `S+3=2` 清零四指针并返回 0 |
| publish-state-0…4，共 5 组 | 原厂前缀生成对应 ID／值；独立原厂存储与读取一致 |
| publisher-unchanged | 新旧状态均为 1，不发布，输出标记不变 |
| builder-state-0/2/3，共 3 组 | 属性与源状态数值一致，按上节分支构造，普通六系数和表为零 |

ordinary、alternate、wrap 的原厂浮点读取指令 `1015e064` 各读取 864 项，输入缓冲前后完全一致；未映射 MMIO、RAW 像素载荷或编码输出，不涉及 NEF 像素试验。73 段包括 5 段发布者前缀，其余 68 段到函数返回哨兵；不是一次连续拍照。v6 的 5 组结果已包含在 v7 中，不重复累计。

**保留了五次受观测钩子影响的失败运行。** 最初带全局 RAM 写入钩子的版本在替代来源用例中错误地走普通来源，记录到第二个属性 ID 为 `ffffffc0` 而非 `303e`。逐指令诊断还显示，前面的 memset 之后，原厂 `1015e0e2` 的 MOVW 没有按预期执行。单独新建 CPU 执行这段 MOVW 的四组对照均正确；项目此前也保存过 RAM 写入钩子影响 Thumb IT/memset 的最小复现（`analysis/local-2026-11-02/unicorn_memhook_check.json`，本地归档未公开）。

接受的 v6/v7 仅用基本块和内存读取钩子，写入效果由调用后内存快照核验；没有改原指令、替换返回值或强改 CPSR。去掉干扰性观察方式后分支与指令、数据一致。这是本地 Unicorn 2.1.4／当前观测组合的限制，不能说成尼康固件错误，也不能由四个短片段对照证明模拟器全面正确。失败的 `isolated-source`、`v2`…`v5` 和各自脚本、日志全部保留，不列为有效结果。
