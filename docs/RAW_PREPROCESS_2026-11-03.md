# 静态 RAW 编码前配置与四路负偏移

日期：2026-11-03，Asia/Shanghai。初代 Nikon Z6 C3.80。接续 [主 RAW 与 AF/PdAf 路径](RAW_BUFFER_ROUTES_2026-11-03.md)，本轮继续定位暗信号、RAW 校正和彩圈相关处理。

本轮最直接的新线索是：**原厂代码从标定数据取得一个数值，在静态照片参数中保存，并把其相反数写入四个槽，最终打包到硬件寄存器；配置 `0x3e1` 参与上游提前返回零的分支。** 已验证数值链和分支，尚未证明它在 RAW 输出取样点之前执行、硬件如何解释这些位，以及是否为暗信号/黑电平扣减。不能把它标为天文补丁。

同时恢复了主 RAW 处理的输入、可选替换输出、两组硬件地址空间与配置分支。20 组隔离用例通过，两次 QEMU 观察保存 19 / 51 条事件。没有修改固件文件或模拟像素算法，没有有效 NEF 或真机效果结论。

## 与最终目标的关系

| 目标 | 本轮推进 | 尚缺的关键证据 |
| --- | --- | --- |
| 保留暗信号 | 找到统一负偏移的标定来源、静态对象字段、四槽打包及 `0x3e1` 分支 | RAW 输出是否经过该处理；偏移、裁切与真实暗电流的关系；上游是否已丢失信息 |
| 关闭静态 NEF 前 RAW 校正 | 主 RAW 输入/替换输出已连接到处理驱动；验证可选输出会改变两个控制字段 | 硅片运算顺序、各处理的真实使能及 RAW 输出取样点；静态完整执行与有效 NEF |
| 消除彩圈 | 建立参数生成者到处理单元的可追踪入口 | 尚未确认二维颜色增益或造成彩圈的硬编码空间校正；统一偏移本身没有二维位置参数 |

原有 `0x29c / 0x29e` 和 AF/PdAf 证据保留，不能与本轮的 `0x3e1` 混为同一开关。

## 1. 主 RAW 处理到硬件配置

以下调用关系来自原始固件反汇编；后面明确列出哪些在 QEMU 窗口中实际命中。

```text
0x100ae33e：构造处理请求 0xc233525c
  input handle  = capture_object+0x1f8
  optional out  = capture_object+0x1fc
  parameter A   = *(capture_object+0x3a4)+0x394
  table B       = stage_request+0x588
  final 8 bytes = stage_request+0x3f94
  → 0x100b4c78(instance=1)
  → 0x100b5716：构造指针包及具体参数
  → 0x100d67f4：消息 0x42170801，队列对象 0xc1d8833c
  → worker 0x100d62e4
  → 0x100d5c86：驱动配置
```

实例 1 的工作函数为 `0x100d62e4`；邻近的 `0x100d63f0` 是另一队列的工作函数，不应误认。驱动通过对象 byte+4 选择地址：`0x20380000 + (bank << 18)`，bank=1 为 `0x203c0000`。软件请求 instance 与实际驱动 bank 的联系来自初始化和工作函数；数值本身不代表照片菜单模式。

| 字段 | 原厂构造/打包函数 | 寄存器相对所选 bank 基址的位置 |
| --- | --- | --- |
| 主 RAW 句柄 +0x34 像素地址、+0x26 行跨度 | `0x100b37de → 0x1010657a` | 地址组 +0x310 或 +0x320，行跨度 +0x30c |
| 可选替换 RAW 句柄的同类字段 | `0x100b36f0 → 0x10106980` | 输出地址 +0x3ec、跨度 +0x3f0；格式另到 +0x3e8 |
| 请求 +0x1a8 是否有替换输出 | `0x100b33bc`，再经原驱动 | 有输出时 +0x580=1、+0x67c=0x300；无输出时为 0、0x100 |
| 核心参数 byte+0x3e 的低五位 | `0x10106360` | 分别写 +0x120/+0x124/+0x128/+0x12c/+0x130 |

四种 bank×输出存在性组合执行原厂构造和驱动，确认上述地址、跨度和控制字段。输入组在用例中独立由人工请求 byte+0 选择，不能因此认定输入组与 bank 天然绑定。所有像素地址均未映射；这些用例验证字节传递，不读取或写入任何 RAW 像素。

`0x100ae33e` 仅在条件满足且替换句柄存在时填入请求 +0x1a8，返回后交换照片对象 +0x1f8/+0x1fc。这连接到上一轮的 `0x100af648 → 0x100a323e → IMPRAW` 编码输入。原始输入句柄不等于未经传感器或前端处理的 ADC 数据，跳过交换也不能自动满足最终目标。

## 2. 新线索：标定值到四路负偏移

### 已核实的静态数据流

```text
0x1013f8e8：静态对象准备
  → 0x100760b6
  → 0x101e338a → 0x100f6e2e
      读取配置 0x3e1，放入局部请求 byte+0x10
  → 0x1017d504 → 0x101224ce：标定表取值 / 提前返回零
  → 0x1013f93c..0x1013f958
      写 *(capture_object+0x3a4) 的 +0x198/+0x19a/+0x19c/+0x19e

0x100ad5cc 或 0x100ad6f8
  → 0x100c2824 → 0x100c24f2
      owner+0x19c → 参数输入 +0x86
  → 0x101004b4 → 0x10171fae → 0x1019f3d0
      output A = *(context+0xd0)
      A+0x186/+0x18c/+0x192/+0x198 = -input_u16(+0x86)
  → 0x100b3f94：packet+0x34 指向 A+0x17e
  → 0x100d5c86 → 0x10107262(packet_block+6)
      四个值各取低 13 位，写 bank+0x710 / bank+0x714
```

这里的 A 是 `owner+0x394`，不同结构中相同偏移不能互相替代。`0x1019f3d0` 还写入四个乘法系数及其他控制字段，不宜直接将整个函数 NOP。

六组隔离用例使用源值 0、64、300，各在两个 bank 下运行未修改的原厂计算、指针构造及寄存器打包器。源值 300 时，四个 RAM 半字均为 `0xfed4`，各自低 13 位为 `0x1ed4`，两个寄存器均为 `0x1ed41ed4`。另外的四个系数保持为用例设定得到的 768 / 512 / 512 / 1024。

**已验证的是 CPU 取负、槽位和打包规则。** 将这些 13 位解释为硬件有符号像素偏移仍需验证；也没有证据证明这个单元影响 RAW 保存，而非只影响后续预览/图像处理。暂用“统一负偏移候选”，不命名为 True Dark Current 或已确认的黑位开关。

### `0x3e1` 分支与标定布局

`0x101224ce` 的输入 byte+0x10 非零时，提前返回 0，不执行模式选择及标定取值。上游 `0x100f6e2e` 将配置 `0x3e1` 的返回字节填在这里。这个事实不意味着 `0x3e1` 会关闭其他处理。

普通分支使用模式组和数值索引读取：

```text
calibration_base = *(0xc18fa954+0x14)
address = calibration_base + 0xbc7f6 + group*396 + index*12
value = u16(address)
```

分组及较小索引还涉及 `0x1011ee50 / 0x1011c0b0`；本轮没有解释这些模式对应的拍摄设置。隔离测试仅覆盖 group=0、末尾索引 31/32，以及输入 byte+0x10=0/1/2。人工表值分别为 300/320；普通分支返回表值，两个非零标志均返回 0。没有改写持久设置或给真机提供补丁。

## 3. 为什么“跳过上传”不能直接视为关闭处理

原厂驱动先处理核心参数，再分支：

- bank=1 且 packet+0xcc 非零时，只继续使用 packet+0x58、+0xc8 两块特殊参数，然后进入结尾。普通 RAW 地址及大多数参数打包器不走这一分支。
- 其他情况走普通配置，其中可能包含 RAW 输入、输出及各参数/表。
- `0x100b3f94` 的表源 byte+0x39a8 非零时提供 packet+0x2c；为零时直接将 packet+0x2c 置空。`0x10106d6a` 上传的是 **0x40 字节 / 16 个字**，不是 64 个条目。

配置阶段隔离实验先留下旧寄存器值，再选择上述分支，确认被跳过的 RAW 地址/表不会被这些函数自动清零。特殊分支仍提交 +0xb1c..+0xb34、+0xdf4..+0xe10 的参数。

实验显式传驱动 r2=0，选择其现有的配置阶段入口；未执行真实工作函数中的初始化、复位、启动及完成。因此不能推断真机整体执行后一定保留旧寄存器或仍执行旧运算。这里证明的是：**空指针、上传标志、配置模式与真正的处理使能必须分开验证。** 五个核心位也尚未取得黑位/坏点/阴影等物理名称。

## 4. 运行跟踪与零数据限制

两次跟踪继续使用固定上游 `419a1f2a91a1f2d3a0209027c29606475f7fe26f` 及此前已披露的 shooting 启动夹具，包括 `0x29e=1`、合成输入和硬件辅助。没有新增客体补丁或强制完成事件。

| 运行 | 观察及边界 |
| --- | --- |
| `native-preprocess`，19 条事件 | 观察到参数指针构造和 bank=0 配置；取得静态主 RAW 对象及参数所属对象。主 RAW 处理/编码入口未命中 |
| `native-offset`，51 条事件 | 观察到标定查询、取景四槽计算/打包、静态 `0x100760b6` 及写入 owner+0x19c 的位置；仍未命中静态 `0x100ae33e` 和编码入口 |

第二次运行静态写入值及最终 owner+0x19c 为 0。当前 `calibration_base=0xc9700000`，从 `0xc97bc7f6` 读取的 2772 字节全零；这只是本次模型内指定范围，不能推广为真机标定表为零。观察到的参数计算输入 +0x86 也是零，不能用当前画面无变化验证开关效果。

每个断点在每个 `call_fixture` 窗口只采第一次，不是完整调用轨迹。一个窗口可交错运行取景和静态任务；标定查询的第一次命中不能自动与稍后的静态调用配对。静态关联以对象指针、实际写入点和原指令共同确定。两个运行均未触及观察器的 256 条上限。

## 5. 证据、复现和下一步

证据目录为 `analysis/raw-preprocess-2026-11-03`（本地归档，未公开），包含反汇编、两次运行会话、寄存器内存图、实际执行脚本快照、命令及 stdout/stderr。`analysis/raw-preprocess-2026-11-03/verification.json`（本地归档，未公开） 核对原始升级包和四个解包模块哈希、运行记录、20 组用例与 36 段精选反汇编。

接下来的具体优先级：

1. 沿 `0x101224ce` 的标定表来源、模式选择及配置 `0x3e1` 的其他消费者，确认该偏移的含义与覆盖范围。跟踪 `0x1019f3d0 → 0x10107262` 是否进入静态 RAW 实际输出；先区分 RAW 与预览，不能仅因“取负”就当作暗电流扣减。
2. 沿 RAW 替换输出 +0x1fc 与 +0x580/+0x67c 控制字段，确定硬件 RAW 输出取样点与四槽所在单元的先后关系；继续独立查找上游裁切、邻域过滤和真实使能。工作函数的初始化与双 bank 配置也要纳入，不把配置阶段实验外推为整条通路已关闭。
3. 从已连通的静态参数生成 `0x100c2824 → 0x10171fae` 及表生成 `0x100c2842 → 0x10171dbc` 定位具有二维坐标、空间增益和颜色依赖的处理。现有负偏移、16 字表、编码一维表均未证明是彩圈校正。
