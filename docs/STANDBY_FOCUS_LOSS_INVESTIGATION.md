# Nikon Z6 待机休眠线控镜头丢焦点问题调查与技术复盘报告

- **状态**: **UNRESOLVED — 已重新列入下一阶段优先待解决列表 P3**（详见 [NEXT_STEPS.md](NEXT_STEPS.md)）
- **记录日期**: 2026-11-15（2026-11-19 状态更新）
- **涉及机型与镜头**: Nikon Z6 (固件版本 C3.80) + 唯卓仕 (Viltrox) AF 16mm F1.8 Z 等 Z 卡口线控步进电机镜头
- **核心问题描述**: 
  在野外拍摄星野时，用户将唯卓仕 AF 16mm F1.8 Z 手动对焦至无穷远真合焦点（此时屏幕标尺显示约为 `5.2m`）。当相机进入自动待机休眠（待机定时器超时黑屏），用户半按快门或自动测光唤醒相机后，镜头焦点自动丢失并跳回出厂假无限远物理零点（`∞`），导致拍出的星点严重脱焦虚化。实测关机冷启动（彻底断电再开机）可以正确恢复，但待机休眠唤醒却必然跑焦。

---

## 1. 尝试历程与失败证据汇总

针对该问题，先后设计并构建了 4 轮固件 Patch 方案并在真机上进行刷机验证，均反馈“**没用，重新做**”。以下记录每一轮的切入点、执行细节与失效原因：

### 第 1 轮尝试：`0x10525ad6` 取景启动挂钩
- **挂钩位置**: `CCaptureCameraControl_StartCameraLiveView` 退出处 (`0x10525ad6`)。
- **设计假设**: 以为每次相机唤醒重新显示 LiveView 取景画面时都会经过该函数。
- **真机实测结果**: **完全无效**。
- **失败原因复盘**:
  全链路逆向表明，`CCaptureCameraControl_*` 系列函数仅在**通过 USB / PTP 协议连接计算机进行联机联控实时取景**时才会被调用。在机身脱机单机拍摄、由半按快门或测光定时器从休眠中唤醒时，根本不会走联机控制状态机，挂钩指令从未被执行。

### 第 2 轮尝试：`0x1025e8c2` 硬件时钟电源 Resume 退出挂钩
- **挂钩位置**: 系统底层电源管理器 Resume 分发器 (`0x1025e832..0x1025e8c4`) 退出处。
- **实现手段**: 在 ROM 洞中手动拼装 Opcode 9 RPC 命令（`0x10170e54` snprintf -> `0x103fe810` send -> `0x103fdff8` finish）。
- **真机实测结果**: **完全无效**。
- **失败原因复盘**:
  1. **时序严重过早**: `0x1025e8c2` 位于硬件时钟与电源驱动恢复的最前阶段，此时卡口供电刚恢复，镜头内部单片机（MCU）尚处于冷复位自检与 SPI 物理通信握手阶段，无法接收并处理任何高层 RPC 指令。
  2. **代码逻辑缺陷**: 结束桩函数 `0x103fdff8` 要求 `r0` 为有效的镜头服务对象指针，手写的汇编代码传入了 `r0 = 0`，导致内部 `cmp r0, #0; beq` 直接跳过返回。

### 第 3 轮尝试：`0x1029a930` 镜头连接完成事件挂钩
- **挂钩位置**: 系统命令分发器处理事件 `0x0410001c` (`eSyscCommandId_MlLensConnectComplete`, Command ID 0x2c) 处。
- **实现手段**: 
  - 检查菜单属性 `0x1ba2`（保存对焦位置）是否为 1；
  - 读取全局镜头对象单例 `*0xc18fb0f4`；
  - 调用官方标准设置恢复导出桩 `0x104abc4e` (`RestoreSettings`)。
- **真机实测结果**: **完全无效**。
- **失败原因复盘**:
  深入分析状态机跳转表（TBB 0x1029a7a0）发现：Command 0x2c 是在 `0x1029a946` 处理，而 `0x1029a91c..0x1029a934` 实际对应的是 Command 0x2b（事件 `0x04100021`）。挂钩点发生了偏移，且没有建立与电源恢复状态标志的联动。

### 第 4 轮尝试：双重保障联动（Resume 标志注入 + 镜头连接 Hook）
- **挂钩位置**: 
  - Hook 1: `0x1029a930`（MlLensConnectComplete 分发路径）。
  - Hook 2: `0x1025e8c2`（Resume 分发器退出处注入标志 `[0xc18d0ab8] = 1`）。
  - 菜单默认值: `0x113a63a0` 设置 `0x1ba2` 默认开启（1）。
- **真机实测结果**: **依然无效**（用户实测反馈“没用，重新做”）。
- **终极失败原因剖析**:
  通过对唯卓仕等第三方 Z 卡口自动镜头的特性深入分析，查明了机身端无论如何调用通用恢复指令都无法生效的物理与固件根源：
  1. **第三方镜头内部 MCU 的独立掉电复位特性**:
     原厂 Z 镜头（如 Nikkor Z 24-70/4 S, 50/1.8 S）在机身待机时保持低功耗通信睡眠；而唯卓仕等副厂镜头在机身关闭主电源待机时，内部步进电机驱动芯片与传感器彻底断电。
  2. **机身未触发重挂载握手序列 (Re-Mount Sequence)**:
     在冷启动（关机再开机）时，机身产生 `0x0410001f` 事件，向镜头发送完整的握手与参数协商指令流，唯卓仕镜头完成自检后接受机身的初始位置配置；而在待机唤醒时，机身认为“镜头物理上从未拔下”，只进行简单的快速时钟同步，并未重新下发镜头初始化报文。
  3. **唯卓仕固件的假无限远固化**:
     唯卓仕镜头的步进电机在断电再上电后，其内置固件自动将电机拉到其固件标定的物理零点（即 LCD 屏幕显示的“假无限远”）。由于缺少完整的握手序列或特定的副厂专用通信指令，机身发送的通用 Nikon RPC Opcode 9 被镜头副厂 MCU 判定为无效状态直接忽略，或者机身内部缓存的 `0x1133` 焦点值在待机重新握手时已被副厂驱动上报的零点覆盖。

## 2. 结论与处理决定

1. **状态定性**:
   该问题并非机身固件中简单的菜单或状态标志位跳过问题，而是涉及到第三方镜头副厂逆向通信协议与机身电源管理握手时序的深度兼容性问题。在没有唯卓仕镜头固件逆向反编译或专业硬件协议分析仪抓包数据的前提下，仅凭盲调机身端 RPC 无法稳定解决。
2. **阶段处理与后续安排**:
   - 在当前正式发布基线（`Modified23`）中已彻底剥离上述未经真机验证生效的待机对焦 Hook 代码，确保正式版固件的纯净度与稳定性；
   - **后续安排**：本问题已列为后续 **优先待解决列表（P3：对焦位置待机记忆）**（详见 [NEXT_STEPS.md](NEXT_STEPS.md)），后续将以本文记录的 4 轮失败根因为反例，从冷启动完整重挂载（`0x0410001f`）与待机休眠前/唤醒后（真实 Command `0x2c` `0x1029A946` 及焦点缓存防覆盖）全链路对比重新立项攻关。
