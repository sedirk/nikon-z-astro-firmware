# Z6 C3.80 首次实机测试前审查

审查日期：2026-11-09（北京时间）。用户已确认相机当前为**原版 C3.80**。

**结论：本候选可进入受控的首次实机测试。** 本轮未发现需要撤销候选的文件、指令边界、调用约定或更新区域问题；建议按同包 `START_HERE.txt` 完成卡上校验、原版文件识别检查后，再手动确认更新。这是工程上的首次测试放行，不是已经完成真机可靠性认证。安装、实际回退和 NEF 效果仍需此次相机测试完成。

本次候选与前轮字节完全相同，没有为了“方便刷入”提高版本号、绕过检查、添加新代码或叠加其他补丁。目标首先是验证曝光相关邻域处理；暗电流、其余 RAW 校正和彩圈继续分项验收。

独立按固定旧字节和固定新字节重建候选，得到与交付文件完全相同的内容；这次复核没有信任旧清单来决定允许修改的位置。两个被省去的函数 `100c2b0a`、`100c2b22` 是 0/1/2 转换叶函数，没有内存写入。所产生的易变寄存器／条件码差异在后续原始指令中被覆盖或不被读取；补丁没有改变调用者需要保留的寄存器。

新增 **96 组原版／候选对照，共 192 次原生函数执行**，覆盖 16 种传入 NZCV 组合、有效和越界枚举样本、两个生成模式。SP、r4–r11 和输入 owner 均保持；属性差异仅为 `+4c/+4e/+4f`。先前 648 组控制矩阵、16 组编码连接对照的证据继续有效，本轮未把它们重复计算成新测试。

## 2. 更新入口与回退方向

前轮已执行原版 ROM 对候选的文件名、版本、CRC、组件预检和写入前缓冲准备。本轮新增**候选 ROM 读取原版 EG**的反向检查，仍通过相同文件层流程。这个结果支持相机正常运行时通过原厂更新菜单换回原版。

升级入口保持原厂 `EG1620??.BIN` 单模块路径；实际名称为 `EG162080.BIN`。原厂返回版本仍为 03.80。菜单仅显示 3.80 无法区分原版和候选，必须同时保留文件校验记录、更新成功画面和后续 NEF。

整包 `Z_6_????.BIN` 另有摘要层，先前 CRC-only 诊断整包仍不应刷入。本次审查包只包含两份有效 EG：一份测试、一份原版回退。尼康官网的完整原版继续保留在项目 `firmware/original/Z_6_0380.bin`；官方文档列出的常规升级范围是 1.00–3.70，因此本审查不把“同版本完整原版必然允许安装”作为回退保证。

## 3. 新追到的真实刷写调度

这里执行的是 ROM 中复制到 RAM 的原始代码，硬件擦写服务以**隔离的内存模型**代替。模型明确在 `c2a10602`、`c2a10616` 等边界拦截；没有连接相机、访问真实 flash 或运行硬件驱动。边界、调用顺序、原生读回比较和错误处理是本轮测试对象，电气可靠性不是。

### 地址和顺序

- ARM veneer `1014a674` 转入 `c2a10c72`，实际只设置更新上下文。前轮把这个停止点简称为“flash 原语之前”不够精确：前轮确实停得更早，尚未进入实际擦写。
- `1014a67c` 返回工作函数指针 `c2a10c29`；实际工作从 Thumb 地址 `c2a10c28` 进入。
- `c2a10d88` 擦除主区域；`c2a10cd4` 编程并逐字比较读回值。
- 主区域为 **`[0x10020000, 0x12960000)`**，43,253,760 字节，330 个 128 KiB 块。小补丁仍然触发整个主区域的更新。
- 正常编程顺序为 `10040000` 起的其余 329 块，最后写 `10020000` 的首块。有效 EG 载荷为 33,502,840 字节，剩余区域按原厂流程填充 FF。
- 起始地址之前的 128 KiB 前缀和区域结束处 canary 在模型中保持不变。这个地址边界不能推出“前缀一定有可用救砖模式”，也不能推出所有非易失标定的位置已全部查清。

### 正向、反向和失败注入

| 测试 | 原生调度结果 |
| --- | --- |
| 原版运行环境 → 候选 | 330 次擦除、330 次编程；全部目标和顺序符合区域；读回成功 |
| 候选运行环境 → 原版 | 同上；原版主区内容完全恢复到预期内存结果 |
| 每次首块擦除服务失败 | 最多 6 次尝试；没有开始编程；最终错误通知为 1 |
| 编程服务声称成功但读回有 1 字节不同 | 原生逐字比较发现差异；6 次编程尝试均被拦下；最终错误通知为 1 |

两例成功的完成通知为 0。这里的“恢复”限定为离线模型中的字节结果。失败重试是重新擦写，并非双备份自动回滚；已经擦除主程序后的断电或持续写入错误，仍可能使机身无法正常启动。

## 4. 剩余风险与本次放行条件

审查已降低拿错文件、文件损坏、补丁越界、调用约定破坏、更新区域错误和菜单正常时原版文件不被接受的风险。剩余风险集中于：

1. **实际供电、存储卡和 flash 硬件。** 文件校验和离线模型不验证电池接触、突然断电或芯片寿命。使用充满且可靠的兼容电池、可靠卡和读卡器；刷写期间按尼康指引保持电源及设备不被操作。
2. **真实启动和拍摄组合。** 候选尚未在这台机身运行；没有改启动流程降低了相关风险，却不能代替首次开机、菜单和 NEF 保存测试。先用单张静态拍摄，逐步扩大测试范围。
3. **故障后的恢复能力。** 同包原版 EG 用于机身仍能正常进入更新菜单时回退。本项目尚无验证过的不开机救砖流程，也没有该机身完整 flash／NVRAM 备份。无法开机时可能需要维修或硬件编程；保留原版文件本身不能消除此风险。

用户已确认原版 C3.80，符合本候选基线。实机操作前仍需确认一代 Z6、可靠电源、卡上文件校验通过、原版 EG 在当前菜单可被识别。先做识别检查并取消，**无需额外刷一次原版来“练习”**。详细步骤在同包 `START_HERE.txt`。本轮没有写入存储卡、格式化介质或操作相机。
