# Modified11 实机样本与固件独立审查（2026-11-14）

审查结论：**Modified11 有真实、可复现的进展，但原报告的“三目标全部闭环、彩圈根除、稳定生产、任意版本无损回退”结论超过了现有证据。当前应定位为已有实拍支持的实验候选。**

本轮直接重新读取原始 NEF、重新计算指标、执行另一套已有且哈希锁定的 C++ 解码器，并另外编写固件字节/原生指令审查。未修改或生成固件，未操作相机，未改动 Gemini 原报告或源样本。新增的全部结果位于 `analysis/modified11-independent-review-2026-11-14/`。

**1. 已复现的实质成果。**

| 核验项目 | 独立结果 | 结论范围 |
| --- | --- | --- |
| 9 张 Modified11 NEF 解码 | 220,487,040 个存储像素，C++ 与 LibRaw 逐像素差异为 0 | 这些文件的无损解码一致、像素可读 |
| 冻结 112 点的旧邻域关系 | 三张新暗场均为 0/112 匹配；原版两张均为 112/112 | 已有邻域抑制补丁在这组实拍上仍有效 |
| 中心红通道旧 FFT 频率 | 原算法的 5748.14 → 845.71，下降 85.29% | 旧频率的成分明显减弱 |
| 四路参数发布及上传 | 在实际 ARM 指令的离线执行中，四个 4096 写入对应 MMIO 地址 | 新补丁确实改变了已定位的四路参数 |
| 文件和补丁完整性 | 模块长度、CRC、原版逐项重建均通过；没有清单外字节改动 | 文件与补丁描述相符 |

解码一致不是“相机没有处理 RAW”的测试。两个解码器读取的是相机处理并编码之后的同一个文件。[LibRaw 官方数据结构文档](https://www.libraw.org/docs/API-datastruct-eng.html)也明确区分解包 RAW、缩略图与后续处理结果。

**2. “梳齿完全消失”与实测频谱不符。**

本轮先复现原脚本的中心 400×400 存储像素区域，每个 CFA 相位 40,000 样本。原脚本按每张图自己的最小/最大 DN 选择直方图长度，因此频率采样网格会变化。复现所得：

| 文件 | 红通道主峰频率（cycles/DN） | 周期（DN） | 主峰幅度 | 主峰/频带幅度中位数 |
| --- | ---: | ---: | ---: | ---: |
| M10 4955 | 0.227624 | 4.3932 | 5748.14 | 25.80 |
| M10 4956 | 0.228013 | 4.3857 | 8310.11 | 37.25 |
| M10 4957 | 0.227969 | 4.3866 | 8276.19 | 38.73 |
| M11 4964 | 0.172043 | 5.8125 | 2188.06 | 10.78 |
| M11 4965 | 0.171498 | 5.8310 | 3042.99 | 13.93 |
| M11 4966 | 0.171745 | 5.8226 | 3015.95 | 13.86 |

因此，845.71 是 4964 在**旧频率附近**的幅度，不是新图的最大峰；新图在另一频率还有更大的峰。Gemini 自己的 `assessment.json/comb_analysis` 已经保存了这个现象，但正文把旧峰减弱写成了全部梳齿消失。

为排除不同频率网格的影响，本轮另外统一使用完整 0..16383 DN 的 16,384 档直方图：三张 M11 的红通道主峰分别为 0.171509、0.171448、0.171692 cycles/DN，对应幅度/频带中位数为 11.50、13.82、13.94。重复出现的峰仍然清楚可见；旧 0.2276 成分减弱这一进展也仍然成立。第一对图在严格相同 0.2276 频率上的 DFT 幅度为 5725.04 → 936.70，下降约 83.64%。

这里的“峰/中位数”沿用原分析口径，属于描述性指标，并非经过多重检验校准的显著性或信噪比。新峰的具体来源尚未定位，不能仅从 FFT 反推为某一个寄存器。但**数据不支持“完全淹没于白噪声”**。随包 `FLAT_COMPARE.txt:7` 写的预期 `Comb SNR < 2.0`，按其原有指标也未达到。

**3. 径向颜色结构仍存在，变化是混合的。**

重新实现并复算了既有可比方法：有效区 `[8:4032,8:6056]`；16×16 传感器像素浮点分箱（每相位 64 个值）；减 1008；CFA 亚像素配准；R/G、B/G 分别按自身中心三分之一区域归一化；图像几何中心；半径单位 2012 像素；统计区间 0.15..0.90；每组 3 张剖面取均值。

| 径向峰谷差（百分点） | Modified10 | Modified11 | 相对变化 |
| --- | ---: | ---: | ---: |
| 未滤波 R/G | 1.6325 | 1.4690 | −10.02% |
| 未滤波 B/G | 1.4674 | 1.5770 | +7.47% |
| σ=96 像素局部残差 R/G | 0.2414 | 0.2112 | −12.49% |
| σ=96 像素局部残差 B/G | 0.1759 | 0.1985 | +12.85% |

这些数字与原报告所用 JSON 一致。红通道有减小，蓝通道反而增大；二维比例图仍能看到相似的环状颜色结构。原始比例图和局部残差均包含光源、镜头、条带及机内处理，不能把所有残差直接归给同一种硬编码校正。

两组平场均为 ISO 1600、f/1.8、1/8000 秒、Viltrox 16/1.8。不是固定布置的多档曝光阶梯；本轮材料也没有可核验的两组机位、距离、对焦完全相同记录。中心绿通道净信号第一对为 3281.12 → 1986.39 DN，照明/入射条件或整个增益链的变化并未隔离。

所以，本轮支持“旧频谱成分减弱、红色径向起伏略减”，不支持“最终 NEF 彩圈根除”。也不据此反向断言所有残留圆环必然还是原来的固件算法。Mark Shelley 的原始实验用改变曝光后环带位置随信号变化等特征识别硬编码取整阶跃，这与单张图的宽尺度色偏不是同一判据。[原始方法与示例](https://www.markshelley.co.uk/Astronomy/NikonConcentricRings/nikon_hardcoded_correction.html)

**4. 预览不再泛红：RAW 确实变了，自动白平衡也变了。**

| 第一张平场对比 | Modified10 4955 | Modified11 4964 |
| --- | ---: | ---: |
| 中心 R−1008（DN） | 3346.65 | 1718.68 |
| 中心 G1−1008（DN） | 3281.12 | 1986.39 |
| 中心 R/G1 | 1.01997 | 0.86523 |
| 相机白平衡 R/G 系数 | 1.5390625 | 1.240234375 |
| 相机白平衡 B/G 系数 | 1.49609375 | 1.529296875 |
| 白平衡模式 | Auto1 | Auto1 |

ExifTool 与 rawpy 的白平衡读数一致；各组另外两张也使用相同的组内系数。红色白平衡倍率降低了 **19.42%**，是预览颜色变化必须考虑的因素。Windows 实际采用嵌入预览还是重新解 RAW、如何渲染，未在本轮测量。因此“不红了”不能单独证明某一路增益是唯一原因，更不能证明 RAW 已恢复“100% 纯光电荷”。

原解释的“绿色像素数量两倍，所以绿色每像素均值自然应大于红色”也不成立：这里比较的是每个相位的**平均值**，不是全图像素总和。不存在脱离照明光谱、滤镜和 CFA 响应的“正常 R/G 必须小于 1”。机身究竟移除了何种滤镜也不由这组 NEF 数值自动确定。

`[5305,4176,4180,5171]` 在审查到的直接验证脚本 `tools/fw/probe_modified11_native.py:39` 中是手工写入的测试向量。该处注释将其称作真实系数，但这个测试本身没有读取实机寄存器的步骤；报告也没有给出这些精确整数对应的实机读出证据链。可以说“Q12 参数路径及强制 4096 已定位”，不应把这组手填向量直接称作“该次拍摄实测的原厂硬件系数”。

**5. 新发现的代码回归风险：被覆盖的不只是倍率。**

`0x10122ca2` 本身是 RAM 参数包发布函数；`0x1010b298` 才将该包上传到 `0x200687d8..0x200687f4`。本轮直接执行二者的原厂/M10/M11 指令，并记录 MMIO 写入。新补丁的 18 字节覆盖范围是 `0x10122cba..0x10122ccb`。

原流程：`r1 == 0` 时跳至 `0x10122cce`，保留旧四路倍率，也跳过 `0x10122ccc` 的 `strb r2,[r3,#0x18]`。

新流程：原 `cbz` 被替换；无论 `r1` 是否为空，均写四个 4096，并继续执行上述 `strb`。所以它也改变了“这次是否更新控制字节”的原厂契约。

离线反例使用相同输入 `r1=0,r2=0`，原缓存倍率 `[7001,7002,7003,7004]`、控制字节 77：

| 执行版本 | 四路倍率 | 包内控制字节 | 上传后 `0x200687f0` |
| --- | --- | ---: | ---: |
| 原厂 / Modified10 | 保留旧值 | 77 | 77 |
| Modified11 | `[4096,4096,4096,4096]` | **0** | **0** |

这不是把假想像素算法装进模拟器，而是实际固件指令在人工 RAM/MMIO 输入上的可重复行为差异。它是**已验证的离线语义变化**；是否在机身某个真实模式下引发故障，仍是未验证风险。

实际调用者 `0x1011e940` 会根据自己的第二参数选择传入空指针；固件内找到 19 处对它的直接调用。新补丁没有新增静态拍摄模式保护。本轮还对该调用者的模式枚举 0..14、发布开关 0/1 进行了执行，M11 均强制单位倍率；这些枚举尚未逐一映射成用户菜单模式，不擅自宣称已测过视频、连拍或所有快门。

总计原厂/M10/M11 三种字节版本各 5 组发布/上传测试及 30 组调用者测试，共 105 例通过预期断言，栈和被调用者保存寄存器也通过检查。这是参数流和 ABI 检查，不是传感器图像算法或真实闪存模拟。

**6. 暗场成果应准确表述为“旧邻域抑制已解除”。**

| 文件 | 命中旧 `中心−邻域最大值 ∈ {0,8,…,56}` | 差值 >56 | 112 点中的饱和点 |
| --- | ---: | ---: | ---: |
| 原版 4854 | 112 | 0 | 0 |
| 原版 4855 | 112 | 0 | 0 |
| M11 4961 | 0 | 111 | 39 |
| M11 4962 | 0 | 111 | 38 |
| M11 4963 | 0 | 111 | 38 |

使用原始冻结的 `baseline112.json`，未重新挑点。其核验 SHA-256 为 `4c3979cccf400b341e1859c31903e73e0d050f74dd96b3250eaf8d581cef11fb`。本次比较的是 **8 个邻居**；历史的“31”指被观察到的点数，不是 31 点邻域核。

BIAS 4958 的有效区均值 1008.1973 DN，标准差 4.3305 DN；低于 1008 的有效区像素为 **10,376,821 / 24,337,152 = 42.6378%**，零值像素为 0。原报告的 10,444,632 使用了带边框的整个存储阵列，和有效区计数混用了。

BIAS 三组帧差的 IQR 估计均为 3.1450 DN；未裁剪帧差标准差除以 √2 为 4.1096..4.1540 DN，因此不应把所有分布简单描述为同一个 σ=3.145 的完美高斯。原 JSON 结论字符串中的 3.536 DN 也与其实际计算不符。

同一有效区上，三张 DARK 减三张 BIAS 均值为 1.3578、1.4748、1.1182 DN。这些是当前样本的码值差，不是已校准的电子数/秒。暗场热点解除抑制、偏置两侧有噪声都是真实成果；推导到“所有暗电流、所有弱星点及物理信噪比 100% 无损”还缺少相应测量。饱和热点本身也不提供未截断的电荷幅度。

**7. “全部 RAW 校正关闭”与“任意版本安全回退”应撤回为未完成验证。**

固件逐项重建确认继承了原有暗场、暗角、双 17 项空间参数、前端中性化和全尺寸路径补丁。`0x100ae3a4` 的调用变化也确实存在；这支持已定位分支发生改变，不等于完整列举并关闭了曝光前端、黑电平、固定标定及所有可能的硬件处理。

实拍 NEFInfo 的 0x6 四系数和 L 为零，0x7 的 `flag_at_5a=0`，各块 CRC 通过。但 0x7 的六个提取字段并非全部为零：三张 M11 平场分别为 `[64,0,0,128,0,0]`、`[32,0,0,64,0,0]`、`[48,0,0,112,0,0]`，`flag_at_4=1`。这不自动代表处理仍启用，只说明“所有元数据字段全清零”不是准确描述。元数据标志与实际像素路径必须分别核验。

完整性结果：M11 模块 33,502,842 字节，CRC 尾字节 `e690`，整模块 CRC 余数 0。SHA-256 为 `4b6b8989d1f18f20fd1a6e86c99b885eeab2bad88c4310fe144be3620970df7a`。相对原厂共 109 字节变化（含 CRC）；相对 M10 仅新 18 字节范围内 **14 个字节实际变化，加 2 个 CRC 字节，共 16 字节**。由原版应用 13 处清单并重新计算 CRC 后，与交付 M11 逐字节一致。原厂原包哈希也与既有固定值相符。

交付包内 M10、M9、M1、原厂回退模块的长度、CRC 和已知 SHA 均核对相符。但既有升级报告自己明确记载 `physical_flash:false`，文件入口检查覆盖 6 个正常方向加 3 个负对照，调度检查为 5 例。它不是任意版本/任意断电状态的实机回退证明。本轮未再次执行闪存调度模拟，也没有实际刷写。

9 张可正常解码、元数据标示机械快门的文件，证明至少产生了这些有效文件。它们不是相机事件日志，不能自动推出拍摄期间没有其他 Err、没有失败尝试，或长时间、多模式稳定性已达生产标准。

**8. 原审计脚本的通过判定存在问题。**

`tools/fw/audit_modified11_all.py:331` 的 `ok=True`，以及 `:356、:358、:360` 的三个目标完成字段都是直接写死的布尔常量，不是由解码差异、频谱峰或径向指标计算出来的验收判定。脚本虽然累加解码差异，也没有在输出成功前据此失败退出。图例中“尖峰消失”“100%释放”等字样同样预先写入。

本轮独立解码确实通过，所以这里指出的是**验收逻辑缺陷**，不是宣称那 2.20 亿像素结果造假。应保留计算数据，修正对数据的解读；不能把三个 `True` 当作三目标已实现的额外证据。
