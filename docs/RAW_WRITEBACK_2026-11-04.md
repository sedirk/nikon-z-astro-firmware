# 静态 RAW 首次写入目的地与替换路径

日期：2026-11-04，Asia/Shanghai。初代 Nikon Z6 C3.80，接续[系数接收与 RAW 完成研究](RAW_WRITERS_2026-11-03.md)。本轮继续服务于保留暗电流、关闭静态 NEF 前 RAW 校正和消除彩圈；没有新增网络调研。

**本轮把同一静态照片的原始 RAW 句柄连到了前端写入目的地，并首次读回该缓冲的完整声明范围：提交前、等待后均为全零。当前模型尚未提供有效的静态 RAW 输入，不能用这一运行验证四路负偏移、0x720 或两组空间表对 NEF 像素的作用。** 后端真实校正写回也仍未实现。两处缺口必须分开，不能只补一个完成事件便宣称得到可用 RAW。

新增一次 QEMU 运行、8 条调用观察（其中 5 条属于本次静态对象），以及 10 组／20 段原厂代码隔离执行。没有修改固件指令或模型源码，没有刷机，没有生成 NEF。原始升级包、四个解包模块与四个既有模型文件的哈希继续保留并校验。

## 1. 原始 RAW 从哪里获得地址

原厂 `100c0362` 调用 `10124184` 分配资源，并在 `100c0372` 将返回句柄写入拍摄对象 `+1f8`。`10124184` 调用 `10123e70` 初始化描述符。它把底层分配起点向上对齐到 512 字节，存入句柄 `+34`；这里初始化的是描述符，未向像素地址写图像。

| 句柄字段 | 本轮从原厂代码核实的用途 |
| --- | --- |
| `+24` | 格式 ID；本次静态对象为 2 |
| `+26` | 字节行跨度 |
| `+28/+2a` | 声明的全尺寸宽／高 |
| `+2c/+2e` | 另一组区域宽／高 |
| `+30/+32` | 偶数对齐的区域起点 |
| `+34` | 对齐后的像素地址 |
| `+18/+1c` | 初始化为 0，`100ae474` 的处理收尾分支将其置为 1；不能当作宽／高 |

前轮交换实验在 `+18/+1c` 放置 6104、4222，仅用于识别被复制的两个字段；这些人工标记不是字段物理含义证据。实际宽／高在上表的 `+28/+2a`。

本次原厂路径为：

```text
拍摄对象 +1f8 → RAW 句柄 +34
  → 前端请求 +4 指向同一句柄
  → 100c001e → 100bd820
       几何参数 → 100d80b4 → 1010a67e → 20069500/504/508
       PC 100bd8dc：句柄 +34 → c25ee224+24
  → 100bd5cc
       100d8112 → 1010a7f8：跨度 → 20069808
       100d812a → 1010a890：两组地址 → 20069850..2006986c
```

`1010a890` 根据通道及地址组选择寄存器，`1010a8c2/c6/ca/ce` 写四个地址；主通道为 0，两组分别从 `20069850` 和 `20069860` 开始。**找到的是 CPU 配置图像写入目的地的指令，不是 CPU 写入像素样本的指令。** 真实数据传输仍依赖前端硬件。

## 2. 同一静态对象的完整内存证据

本次运行结果（`analysis/raw-writeback-2026-11-04/native-writeback/result.json`，本地归档未公开）、调用与内存快照（`analysis/raw-writeback-2026-11-04/native-writeback/events.json`，本地归档未公开）记录：

| 项目 | 本次值 |
| --- | --- |
| 拍摄对象 | `c2cbe588` |
| `+1f8` 句柄 | `c2c07688` |
| 像素地址 | `a448e000` |
| 格式 ID、尺寸、跨度 | 2；6104×4222；9168 字节 |
| 完整读取范围 | `9168 × 4222 = 38,707,296` 字节，包含行填充 |
| 两次读取时机 | `10076a08` 提交前；既有无卡诊断请求及 5000 ticks 等待结束后 |
| 两次非零字节数 | 均为 0 |
| 两次完整 SHA-256 | `22369993f9fe29fa48c16149a547c50b0caa674b4d3afaa1a1c16715e14b8903` |

前端请求 `+4` 与拍摄对象 `+1f8` 指向同一句柄；`100bd8dc` 实际将 `a448e000` 放入 `c25ee248`。随后QEMU 日志（`analysis/raw-writeback-2026-11-04/native-writeback/session/qemu-1.log`，本地归档未公开）第 81813 行记录通道 0 的 `offset=50,value=a448e000,dma_completed=0`。日志是地址配置观察，不是 DMA 完成证明。

完整缓冲以 gzip 保存，提交前（`analysis/raw-writeback-2026-11-04/native-writeback/before-front-submit-raw.bin.gz`，本地归档未公开）、等待后（`analysis/raw-writeback-2026-11-04/native-writeback/after-bounded-wait-raw.bin.gz`，本地归档未公开）各 37,655 字节。解压后逐字节检查及哈希均通过。它们是模型 RAM 的快照，不是相机暗场、可解码 RAW 或 NEF。

两次快照相同不能排除中间写入后恢复、或写入相同的零值；本轮没有完整总线写入跟踪。已设断点的 `100ae33e` 静态预处理、`10106980` 替换输出地址、`100af648` 编码阶段、`100a323e` 编码描述符入口均未命中。这只是本次有限窗口的结果，不代表真机不会执行。

## 3. 当前测试图写入分支不覆盖这组静态配置

两组真实捕获的描述符分别在私有 RAM 中交给原厂 `100bd820` 前缀与 `100bd5cc` 执行。前缀停在 `100bd874`，然后另行提交捕获的地址组，**不是完整连续曝光**。结果中的几何／跨度／八个地址逐字关联到捕获的描述符。

| 配置 | 本轮合成取景 | 本轮静态 RAW |
| --- | --- | --- |
| 原始句柄格式 ID | 3 | 2 |
| `20069500` 原厂生成值 | 0 | 2 |
| `20069504` 原厂生成值 | `07f20000`（2034） | `17d80000`（6104） |
| `20069508` 原厂生成值 | `059a0000`（1434） | `107e0000`（4222） |
| `20069808` 跨度 | 4080 | 9168 |

上表寄存器值来自**原厂代码隔离重放**，没有把模型不支持的寄存器读回当作实测硬件状态。`100bff8c` 将句柄格式 2 映射为配置值 2、格式 3 映射为 0；尚未据此验证真实像素 packing。

固定模型的 `nikon-z6.c:1384..1425` 只在模式值 0、尺寸 2034×1434、跨度等条件匹配时，将测试图写入所选地址组；其载荷是 5,850,720 字节。该条件不接受本轮静态描述符生成的配置。日志中的 167 次 `Z6_RAW_NATIVE0_STREAM` 全部发生在静态地址配置之前。本轮两次完整静态缓冲又均为零，因此已有合成取景不能作为有效静态 RAW 输入证据。

源码摘录保存在模型来源证据（`analysis/raw-writeback-2026-11-04/model-source-evidence.json`，本地归档未公开）。其中注释把几何配置标为 `1010a19e`、地址配置标为 `1010a2e4..1010a412`，与本地 C3.80 不符。本轮从原厂指令重新确认的入口分别为 `1010a67e`、`1010a890`；不直接照搬模型注释地址。模型源码未被修改。

即使以后增加静态图像输送，这也只解决输入来源问题。后端 `20380000/203c0000 +3ec` 的真实校正写回仍须独立验证；既有 448 字节 dummy/drain 写入不能替代它。

## 4. 替换 RAW 的条件不是已确认的校正开关

`100ae33e` 的请求前缀把对象 `+1f8` 放入请求 `+8`。仅在下列条件均满足时，才把对象 `+1fc` 放入请求 `+1a8`：

1. `100ac620` 返回 0，即 `owner[0]` 不在 3、4、5、6 中。
2. `101ba474(owner+170)` 返回 1，即 `owner[190]` 为 0 或 1。
3. 对象 `+1fc` 非零。

本次静态快照为 `owner[0]=0, owner[190]=1`。以其 owner 内容为基础，迁移到私有 RAM，做 8 组对照：观测模式、字段 190 改 0／2、无替换句柄，以及模式 3／4／5／6。请求构造都执行到 `100ae3b4` 即停止；后面的硬件处理未运行。

| 条件 | 请求 `+1a8` | 另行进入编码阶段的有界结果 |
| --- | --- | --- |
| 模式 0，字段 190 为 0 或 1，有替换句柄 | 选中替换句柄 | 到达 `100a323e`，输入为当前 `+1f8` 的描述符 |
| 模式 0，字段 190 为 1，无替换句柄 | 0 | 同样到达编码入口 |
| 字段 190 为 2 | 0 | 该编码阶段提前返回 |
| 模式 3／4／5／6，字段 190 为 1 | 0 | 先到 `101af8e6` 辅助函数，传入当前 RAW 地址和跨度×高度；在此停止 |

这些数值尚未对应到具体用户菜单。原厂静态代码显示特殊模式辅助函数返回后仍会调用编码构造器，但本轮没有伪造它的返回值去继续。省略替换目的地并不等于省略整个处理请求，也不证明前端没有已经修改 RAW。**不将这些字段提供为“原始 RAW 模式”或补丁。**

## 5. 对最终目标的结论和下一步

| 优先候选 | 仍成立的已验证证据 | 本轮后的明确限制 |
| --- | --- | --- |
| 四路负偏移 | 原厂计算、独立配置、`+710/+714` 上传；与 0x3e1、源端正数参数及 BlackLevel 的联系 | 尚无有效静态输入和后端输出对照；不能判定暗信号是否被扣减／裁切 |
| `bank+720` | 标量依赖、限幅参数生成、独立上传 | 参数限幅不等于已证实的像素限幅；最终 NEF 影响未知 |
| 两组空间表 | 接收目的地配置、发布、缓存、生成、上传、同源元数据联系 | 真实物理数据与输出作用仍未知；尚不能命名为彩圈校正 |

下一步沿两个具体边界推进：

- **输入边界**：以已确认的前端句柄、格式、跨度和 `20069850..6c` 为观测点，追完整静态读出／packing／数据写入语义。当前只改候选参数、比较全零输入或继续等待，不能回答像素问题。若补模型，必须把“人工图像输送”单独标注，不为候选擅自添加扣黑、钳位或空间增益。
- **校正输出边界**：沿 `bank+310` 输入、`bank+3ec` 写回、完成状态、交换后的编码输入取得同一请求的有效样本；同时继续找独立使能及硬件输出取样位置。缺少硬件行为证据时，不能由寄存器邻接或同包上传推断三个候选已进入保存像素。

取得有效输入／输出或真机样本后，逐项做单变量、存储样本级对照，再追 NEF chunk 3。当前没有完成暗电流保留、关闭校正或消圈验收；不制作可刷补丁。
