# 前端标定的空间身份与静态候选收敛

日期：2026-11-09，接续 modified4 实拍后的前端标定调查。最终目标仍是保留暗电流、关闭静态 NEF 写入前的 RAW 校正并消除彩圈。

## 本轮结果

**ID0b 已从“未知列表”收窄为带行列坐标的离散位置流；静态临时阶段原本就把它的控制清零。** 本轮实际执行了固件内的完整列表生成器，用已知位置验证输出，并从真实请求生产函数追到关闭条件。基于这一结果，不将“静态 input+47 强制为2”选作当前消圈的首个刷机变量。

ID35 的定长区与上述位置流进一步分开：完整 ID0b 生成器会读取 ID35 中的多个位置清单，但本轮实际读取集合不包括 `ID35+acdf0`；单独改变该定长区首字后，生成的整个 ID0b 输出逐字节相同。因此，ID35 这个资源里的不同区域不能一概叫作坏点表，更不能由位置流的身份推断定长表的身份。

33×4 表则已补齐36字节记录头的逐字段去向，并确认其选择器被19个直接调用点共享。静态临时构造中的调用点是 `1017d7f0`，其父函数 `1017d7b6` 的已找到直接调用点是 `10179d7c`。后续单变量修改需要限定这一静态路径；共享复制器、取景和模式切换分别验收。

当前交付版本维持 **modified4**。本轮没有生成 modified5、没有操作相机或存储卡。原版及 modified1–4、既有照片保持。前轮实拍结论延续：宽彩圈没有整体减弱；modified4 的暗场补丁字节保持，最后一次实机暗场回归通过的是 modified3。

## 1. ID0b：原生代码确实在处理离散空间位置

### 1.1 新接通的生产链

```text
10148e1e / 10148f6a
  → 1024efc0：生成 ID0b
       输入：ID35、ID34、输出指针、工作区、类型
       → 1024d51a：线性位置换算为 x/y，按模式裁剪/抽样，范围检查
       → 1024d17a：编码为16位位置流
  → 1014731c：资源写入包装器（本轮未执行）

1011c2a0：从 ID0b 选对应流，或使用 context+50/+54 显式列表
  → 101229b8 → 100cda34 → 20061264/20061268
```

这与前轮研究的 `10250e28` / **ID0c** 生成器是不同函数、不同输出资源，不合并成果。

`1017d69c → 1011c0fa` 返回 `CAL38+cdfc0` 的几何结构。`1024d51a` 取其中原点、宽度和高度，用除法/余数把 u32 线性位置分成行列；再调用 `1024d486`（横向变换）、`1024d3d4`（纵向变换），最后用 `1026189c` 检查边界。

本轮实验明确使用人工几何：原点0、6104×4222，7组几何项，其余字段为0。它不是机身标定转储。原代码保持只读，未替换函数、未添加像素算法、未执行资源写回，输出和工作区边界哨兵均保持。

### 1.2 可复核的坐标实验

6次完整 `1024efc0` 执行正常返回。输入第一类位置清单位于 `ID35+10/+14`；另一类清单位于 `ID35+7d18/+7d1c`。偏移均为十六进制，前者是数量，后者是 u32 位置数组。

使用后一类清单时，生成的 mode0 数据位于 `ID0b+60`：

| 人工输入坐标 | 原生中间 x/y | mode0 输出16位字 |
|---|---|---|
| 无位置 | 空 | `ffff` |
| (100,200)、(800,500) | (100,200)、(800,500) | `e0c8 2064 e1f4 2320 ffff` |
| (102,200)、(800,502) | (102,200)、(800,502) | `e0c8 2066 e1f6 2320 ffff` |

在这组类型、坐标范围和模式下，`e000+y`、`2000+x` 随输入位置变化，`ffff` 终止。更高坐标及其它记录类型有扩展码，不能把这组简例当作所有流的完整格式。

第一类清单还验证了模式相关变换：例如输入(800,500)在 mode4 中变为(800,186)，mode10 中变为(266,62)，mode15 保持原坐标。这是原函数的裁剪/采样坐标行为，不是软件模拟出来的校正图像。

**已验证事实：**该输出含空间位置，改变位置改变编码；不是仅因数据数量或命名猜测其空间性。**仍属推断：**这很符合固定缺陷位置处理的用途。硬件对这些位置具体做替换、插值、抑制还是其它运算，以及它对某张实际 NEF 的影响，另行验证。

证据：mode0（`analysis/raw-spatial-identity-2026-11-09/id0b-mode0/result.json`，本地归档未公开）、坐标移动（`analysis/raw-spatial-identity-2026-11-09/id0b-mode0-shift/result.json`，本地归档未公开）、完整生成器反汇编（`analysis/raw-spatial-identity-2026-11-09/coordinate-setup.txt`，本地归档未公开）。

## 2. ID35 定长区：与位置清单明确拆开

前轮定位的静态 mode1 定长输入为 `ID35+acdf0`，长24416字节，即6104×4；其控制为 `CAL38+540+record_index*80` 的首字节，经 `1011c798` 写入 `2006103c`。这里乘数80为十进制。

本轮新增两个区分证据：

1. 完整 ID0b 生成器对人工 mode0 两点输入的 ID35 读取偏移为 `10, 3e94, 7d18, 7d1c, 7d20, 1212c, 26180, 426a4, 474c8, 4940c, 4c2f0, 9a4f4, a6e44`；其中多数为各清单的计数。
2. 在同一输入上，仅把 `ID35+acdf0` 的 u32 改为 `a55a5aa5`，整个 `25fff8` 字节输出保持相同，SHA-256 均为 `a35da2c961c5a3871900e179dfa99702d380a490e472f75b86cae93450f84737`。此次执行也没有读取被改位置。

这些结论限于披露的输入/执行。它们足以把“生成 ID0b 的位置清单”和“静态前端定长数据”作为不同研究项；不据此断言定长区在任何函数里都不会用于缺陷处理。

定长区按图像宽度组织的假设仍成立为线索；其4字节单位究竟是系数、掩码还是索引，需要真实内容或另一个数据处理消费者作区分。下一轮仍优先追这个区域，保留原来的 `2006103c=0` 控制条件。

证据：定长区独立扰动（`analysis/raw-spatial-identity-2026-11-09/id35-fixed-separation/result.json`，本地归档未公开）、引用搜索（`analysis/raw-spatial-identity-2026-11-09/id35-data-xrefs.json`，本地归档未公开）。

## 3. ID0b 关闭条件的真实来源与静态时序

### 3.1 来源不是猜测的相邻配置编号

原函数链实际执行核对为：

```text
配置 3df
  → 1013f0b2：请求源 c236f620+256
  → 101e30ac：608字节请求复制至 c236d378
  → 100f64a0：静态 input+47
  → 10179962，10179a76/7a：context+5a
  → 1011c53c：ID0b 控制字段
  → 100cda0a：20061250
```

这个来源与 modified4 的 `配置3d2 → context+5d → bit11` 分开。8组实验覆盖配置0、1、2、255及 temporary=0/1，使用非零标定控制作为正对照；配置、源固件保持。列表正对照显式使用上述生成结果的 mode0 指针和5个字，不把人工列表选择当作机身自然选择结果。

| temporary (`context+84`) | policy (`context+5a`) | 非零 CAL 控制的输出 `20061250` | 本次列表分派 |
|---:|---:|---:|---|
| 0 | 0、1、255 | 1 | ID0b；人工显式列表上传16字节 |
| 0 | 2 | 0 | ID0b 门控提前返回，旧描述符保留 |
| 1 | 任一上述值 | 0 | ID35；mode1 指向 `ID35+acdf0`，24416字节 |

ID35 的 `2006103c` 在这些测试中始终为1；因此 ID0b 策略没有顺带关闭 ID35。

### 3.2 对下一版固件的实际取舍

`10179d0c` 的原生静态阶段在 `10179d4a` 设置 temporary=1，依次调用 kind0、kind1 和静态前端构造；在 `10179dd4` 清 temporary，随后进入其它阶段。前轮 modified4 QEMU 的真实指令跟踪已观察到这段顺序，本轮重新按其原始事件核对，未重跑或改写旧跟踪。

因此，在**这段已观测静态临时窗口**内，强制 policy2 不会再改变 `20061250`，因为原厂 temporary 条件已经把它清零。其它静态模式、后续阶段另计，不能扩大成“ID0b 永远与任何 NEF 无关”。

**决策：**暂不制作 `100f64a0 → mov.w r0,#2` 的刷机包。它虽有很窄的静态输入修改位置，但目前更可能改变非临时阶段，当前消圈测试价值低于 ID35 定长区及33×4链路。这是基于原代码与非零对照的候选筛选。

证据：8组来源/门控回放（`analysis/raw-spatial-identity-2026-11-09/id0b-static-scope-v2/result.json`，本地归档未公开）、静态阶段指令（`analysis/raw-spatial-identity-2026-11-09/static-stage-scope.txt`，本地归档未公开）、来源指令（`analysis/raw-spatial-identity-2026-11-09/producer-identity.txt`，本地归档未公开）。

## 4. 33×4：头部作用、共享范围与下一修改边界

300字节源记录由36字节头部及264字节表体组成。头部没有在复制器中参与像素坐标计算，原样或扩宽送入控制寄存器：

| 源记录相对偏移（hex） | 原生处理 | 目标寄存器 |
|---|---|---|
| 00/02、04/06、08/0a、0c/0e | 四对u16，分别装入四个u32 | `200686e4/e8/ec/f0` |
| 10、12 | 各一个u16 | `200686f4/f8` |
| 14/16 | 一对u16 | `200686fc` |
| 18、1a | 各取一个字节 | `20068700/704` |
| 1c | 此复制器不读取；使用 context+dc / 保留状态生成 | `20068708` |
| 1e | 一个字节 | `2006870c` |
| 20、22 | 各一个u16 | `20068710/714` |
| 24..12b | 33×4个u16 | `20068f00/68f44/68fcc/68f88` 四组表 |

四对u16可能是坐标，也可能是阈值/范围。**目前没有真实 CAL38 记录值或硬件定义支撑这两种解释中的任何一种。** 不能把人工夹具中的四对数值当作传感器中心，也不能选一个猜测的“单位增益”填满表。

`20068708` 是已有保留状态参与的交替控制；context+dc非零时强制1。复制器的 `1011e242 cmp r1,#0` 条件标志一直供 `1011e286 beq` 使用。若用会改变标志的短 `movs` 随意替换中间加载指令，会连带改变这条分支；后续补丁必须审查标志存活范围。

直接调用清单：`1011e2ce` 的19个已找到调用点包括取景/模式构造和 `1017d7f0` 静态构造。共享复制器 `1011e23e` 的已找到直接调用点为 `1011e362`。搜索覆盖 Thumb 直接分支及两个奇数函数指针的字面量；不冒充间接调用的穷尽证明。

**静态单变量候选的边界已经具体化：**优先在 `1017d7f0` 所属静态调用处收窄，再只改变一项已识别控制；原 CAL、主控其余位、ID35/ID0b、旧暗场补丁、其它调用点保持。直接跳过调用会留下旧表/寄存器，不能等同关闭；对共享复制器全局打补丁也不满足静态限定。

证据：头部逐字段反汇编（`analysis/raw-spatial-identity-2026-11-09/table-geometry.txt`，本地归档未公开）、19个调用点（`analysis/raw-spatial-identity-2026-11-09/table33-call-scope.json`，本地归档未公开）。前轮单项到寄存器及完整静态构造结果见[前轮报告](RAW_FRONT_CALIBRATION_2026-11-09.md)。

## 5. 下一步与产物状态

1. **保留 ID35 定长区与33×4为优先目标。** 读取真实 CAL38 300字节记录、配套几何和 ID35 定长区，或找到硬件端/其它原生处理消费者，用实际数值判断坐标、信号阈值或系数。原版更新包的主模块不含前轮目录指向的这些存储内容；当前连到电脑的设备中未出现 Nikon 相机。
2. 单变量计划分别锁定 `10179d56`（静态 ID35 全局配置调用）和 `1017d7f0`（静态33×4构造调用）；只选择一个已识别的控制进入下一候选，不同时关闭两路。
3. 新候选与 modified4 比较时，继续校验三处已验证暗场修改、已有中性化修改、所有非目标寄存器和保留状态；有非零正对照后再做安装前审查。
4. 实机判据继续使用固定机位/焦点、多信号级、较慢快门的 CFA 平场比较，另回归112个暗点；当前1/8000秒屏幕宽环与细密量化环分开。此次没有要求用户重新刷机。
