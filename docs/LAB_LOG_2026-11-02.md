## 4. 阅读源码得到的模拟器边界

以下内容来自上游源码和文档，属于**作者报告 / 源码陈述**，本机尚未运行验证。

- CPU 模型为两个 Cortex-A15 和 GIC；作者注明 CPU 型号、CBAR、GIC 版本和完成时序是为能运行而选的，不是已识别的芯片规格。
- MAIN 加载地址和初始 PC 都是 `0x10020000`，长度 33,502,842。
- RAW 几何 `{2034, 1434, stride 4080, 64, 4095}` 用于照片取景（Live View）配置，不是 6048×4024 的完整静态照片。
- 图像链路：合成或自选 RGB 图 → 12 位 RGGB → 实验性 RAW 传输 → **功能性 ISP（简化模型）** → NV12 → 原厂 GPU 合成 → LCD → QMP 截图。
- 源码明确说明：EX MCU 测试端 “does not … drive a shutter, supply calibration, or produce sensor samples”；统计单元 “calibration, AF and accumulation units are not bit-accurate”。
- 日志标记如 `raw_batch_written=1 physical_timing_verified=0`、`packing_verified=0`、`frame_completed=0` 都是模型自报的状态，不能当作真机行为。

**对本项目的意义（判断）**：模拟器可以用来让原厂代码跑到相关路径，然后观察调用、寄存器写入和缓冲区，这对定位处理代码有帮助。但它的 ISP 像素算法是作者写的简化模型，在模拟器里“关掉某个处理后图像变化”不能证明真机也一样。静态 NEF 拍摄流程在 Z6 QEMU 中尚未打通，这一点需要实际运行确认。
