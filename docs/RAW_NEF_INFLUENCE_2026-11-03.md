# 0x3e1、四路负偏移与 NEF 保存内容

日期：2026-11-03，Asia/Shanghai。初代 Nikon Z6 C3.80。接续 [RAW 编码前研究](RAW_PREPROCESS_2026-11-03.md)，按用户要求优先确认这两个候选是否影响最终保存内容。目标仍是保留暗电流、关闭静态 NEF 写入前的 RAW 校正、消除彩圈。

本轮已把同一组标定值连接到 **NEF 的 BlackLevel 元数据写入函数**，也把主 RAW 的处理后句柄、编码输出描述符连接到 NEF 数据分块。**尚未证明四路负偏移改变了保存的 RAW 像素，更没有验证暗电流保留或消圈。** 所有非零对照均是原厂指令在人工内存中的隔离实验，未生成完整 NEF；没有刷写或生成可刷补丁。

同日最新接续见 [RAW 输出、四槽控制与相邻参数](RAW_OUTPUT_ROUTING_2026-11-03.md)：又确认同一标量影响 bank+720 的有上限参数，并恢复缓存限制、独立输出控制和空间表上传链。下文是本轮当时的证据范围。

## 2. 从 0x3e1 到 NEF BlackLevel 的新证据

配置读取器 `0x101cb734` 的字节表基址为 `0xc20aa7c8`，0x3e1 对应 `0xc20aaba9`。既有静态分支如下：

```text
0x100760b6 → 0x100f6e2e → 0x1017d504 → 0x101224ce
  配置非零：返回 0
  配置为零：从标定记录 +6 取 u16
→ 0x1013f938..0x1013f95c
  保存到 owner+0x198/+0x19a/+0x19c/+0x19e
```

新定位的文件封装器 `0x100b1634` 保存 `owner` 到 `package+0x34`，传给 NEF 构造器的请求起点是 `package+0x30`，因此其 `request+4` 指向同一 owner。NEF 分支 `0x1026db48 → 0x1026d8a4 → 0x1026d7ee` 构造 Nikon MakerNotes；组号为 5。

原始启动复制表把 ROM 数据还原为 `0xc18d38a0 → 0xc18d36a0`。NEF 配置选择 0，组 5 的标签列表位于 `0x11537b52`，包含 `0x003d`。原厂选择器 `0x1028d6a0/0x1028d6ac`、过滤回调 `0x1028d3c2` 的隔离执行确认该标签被选择、过滤结果为 1。

ROM `0x11537028` 的 16 字节描述符为：

```text
3d 00 03 00 04 00 00 00 00 00 00 00 d9 a9 28 10
tag=0x003d, type=3, count=4, callback=0x1028a9d9 (Thumb)
```

`0x1018434e` 的标签构造逻辑复制描述符前 12 字节并调用末尾函数指针。回调 `0x1028a9d8` 从 `*(request+4)` 依次读取 owner 的上述四个 u16，写到元数据游标，设置 IFD 数据偏移，游标前移 8 字节。此标签由 ExifTool 标为 **BlackLevel，int16u[4]**；名称依据是外部资料，四个值的数据流依据是本机原厂固件。[ExifTool Nikon 标签表](https://exiftool.org/TagNames/Nikon.html)。本轮下载快照与来源哈希在证据目录中。

新增三个用例独立执行原厂查询、四值存储、封装器和标签回调。输入为人工非零标定值 300，其他路径不等同于真机初始状态：

| 0x3e1 输入 | owner 的四个值 | 生成的 0x003d 负载 | 四槽负偏移参数（另组实验） |
| --- | --- | --- | --- |
| 0 | 300、300、300、300 | `2c01 2c01 2c01 2c01` | 四个 `0xfed4`，低 13 位为 `0x1ed4` |
| 1 | 0、0、0、0 | 8 字节零 | 四个零 |
| 2 | 0、0、0、0 | 8 字节零 | 四个零 |

这些回调测试使用原始标签描述符、人工可写头部内存和未映射的 RAW 数据地址，验证的是元数据字节。没有运行全部 MakerNotes 回调、整个文件写入或独立 NEF 解码。**标签写的是正数标定值，负偏移写的是另一组硬件参数；两者不能混为同一写入。** 后续图像对比必须分别检查原始像素、黑位元数据和解码器解释。

## 3. 0x3e1 还改变前端的正数参数

静态照片参数入口 `0x10179962` 把输入 `+0x43` 写入源上下文 `0xc18fa844+0x5b`。注意其中 r5 曾加 0x10，指令显示的 `+0x4b` 对应上下文实际 `+0x5b`。取景入口 `0x1017c020` 把输入 `+0x47` 写入同一字段。它们来自调用方读取的 0x3e1。

`0x1011ebb8` 使用标定记录 `cal_base+0xbc7f0+group*396+index*12`。记录的 `+6` 正是前述标定标量所在字段。函数将记录部分字段复制到 `0xc29a3894`，发布到 `0xc29a34c0+0x40`；若上下文 `+0x38` 非零或 `+0x5b` 非零，输出块 `+6` 清零。

```text
0x1011d548：调用 *(0xc18fa954+0x0c)
→ 0x100bcd86：复制源参数包
→ 0x100bccd0：按非空指针分发
→ 0x100d82e0 → 0x1010b2f0
→ 0x20068804、0x20068808、0x2006880c
```

`0x1010b2f0` 将前两个 u32 各旋转 16 位后写入寄存器；标量位于 **0x20068808 低 16 位**。四个隔离用例覆盖 0x3e1 输入 0/1/2，以及独立 `+0x38=1` 门控；原厂参数入口、构造器和复制/分发回调均实际运行，停在后续更新控制 `0x100d7de2` 前。人工记录 `[101,202,303,300,405,606]` 产生寄存器 `[0x006500ca,0x012f012c,0x00000195]`；门控时中间寄存器变为 `0x012f0000`。

这与 AF/PdAf 方向的 **0x2006b3xx**、四槽负偏移的 **0x20380710/714 或 0x203c0710/714** 是不同寄存器区。QEMU 也实际观察到源回调指针 `0x100bcd87`，以及六次 `0x1010b2f0` 入口，LR 均为 `0x100bcd5b`，但本轮输入均为零。

“正数参数先加偏置、后级再减去，可能构成前后补偿”只是工作假设。当前没有证据把 0x20068808 定名为真实像素加法器、光学黑位钳位或暗电流扣除。两处表项选择是否在所有静态模式下同步也未证明。

## 4. 四路参数的最终化与 RAW 保存指针

参数生成后还执行 `0x100ad858`。当 owner+0x2815 为 1 时，它把四个增益槽改成 512（原厂 `0x101c7dfc` 返回值），**不清除相邻负偏移**。两组原厂函数隔离用例均保留四个 `0xfed4`。目前没有给该选择字节赋予菜单名称。

`0x100ae33e` 同时提交主 RAW 输入、可选替换输出及这些参数；其返回后的 `0x100ae41e..0x100ae438` 在有替换输出时交换 object+0x1f8/+0x1fc，并复制句柄元数据。编码入口 `0x100af648` 随后将 `*(object+0x1f8)+0x24` 交给 `0x100a323e`，编码输出描述符是 `*(object+0x330)+0x50`。

六组实验覆盖处理模式全局字节 0/1，以及 owner+0x190 为 0、有无替换输出，和其值为 2 的分支。**处理模式全局字节是 `0xc188d8c4`，不是 0x3e1。** 请求 `+0x374` 在该字节非零时为 0、为零时为 1。本轮 QEMU 实际读到该字节为 1；不能假设静态请求固定使用模式 1。各分段分别执行，处理调用停在提交入口，交换块单独进入；没有伪造硬件处理已经完成。

进一步已连接编码输出到文件分块：

```text
0x100b1634(type=1, owner, encoded_handle, ...)
  package+4 = encoded_handle+0x50
  request = package+0x30
→ 0x103269ac → 0x1026e078 → 0x1026db48
  request+0x2c = raw_descriptor+0x0c 中的长度
→ 0x103269b0 → 0x10271316 → 0x1027176a
  type 1 的分块顺序 [0,7,8,5,6,3]
  chunk 3 经 0x10271226 → 0x102710b6 取 RAW 数据
→ 0x1027185c → 0x103fabac：交出数据地址及长度
```

原厂封装器、长度提取块、分块顺序函数及 chunk 3 选择器的隔离执行，得到同一人工编码地址 `0x64000000`、长度 `0x123456`、填充长度 0；数据地址未映射，没有计算或读取实际像素，没有运行文件 I/O。该结果补齐软件保存关系，**仍缺少四槽单元到 RAW 写回像素之间的硬件关系**。

四组处理驱动对照还确认：普通分支上传输入/输出地址以及负偏移；bank=1 且 packet+0xcc 非零时跳过这组配置，只进入特殊参数分支。测试用 r2=0，省略复位/启动，以人工哨兵验证“未写入”，不能据此宣称硬件运算关闭或实际寄存器状态已知。完整静态调用会使用不同复位参数，其他工作函数也可能配置双 bank。

## 5. 其他消费者与尚缺证据

原固件中精确扫描 `MOVW r0,#0x3e1`，得到七处紧邻配置 getter 的直接消费者：`0x100f5bf8、0x100f610e、0x100f64d4、0x100f6b38、0x100f6e7a、0x1024eba6、0x1024fd16`。前四处参与源参数，第三处是上述静态入口；第五处参与标定标量查询。后两处还涉及给三个半字量加该标量、在采样平均量上减该标量后比较。后两条路径的拍摄场景和物理含义尚未定名。扫描不覆盖其他寄存器装载、间接或计算得到的索引，不能称为完整消费者清单。

两次新的 QEMU 运行分别保存 64、78 条观察，观察点每个 call_fixture 窗口只捕获首次命中，不能当成每次调用的完整时序。静态源参数和保存对象标量存储被观察到；静态主处理 `0x100ae33e`、提交 `0x100b4c78/0x100b5716/0x100d67f4`、编码 `0x100af648`、文件封装 `0x100b1634` 在这两个窗口中均未命中。

模型内所读取标定区域仍全零，保存对象标量也是零；因此非零因果关系来自人工标定的隔离实验，不能用模拟画面不变或寄存器为零来验收。未获得有效 NEF、真机内存或用户暗场/平场样本。

下一轮按以下顺序推进：

1. 从主 RAW 写回 `0x10106980`、控制 `bank+0x580/+0x67c` 和四槽打包器 `0x10107262` 反向核对硬件选择、真正使能与输出分支，先证明四槽是否位于保存 RAW 的取样点之前。分别保留 bank、复位和请求模式条件。
2. 同时追 `0x20068808` 的使能/邻近控制及源缓冲写入者，区分必要偏置、扣减、钳位与统计参数。设计能分别改变前端参数、后端四槽、元数据的实验，避免只改 0x3e1 后把多处变化混为单一效果。
3. 保持二维空间校正独立支线：从 `0x100c2824 → 0x10171fae`、`0x100c2842 → 0x10171dbc` 的参数与表来源定位空间依赖；不把统一偏移、BlackLevel 标签或一维编码表当作彩圈原因。热像素/邻域过滤也仍需独立定位。

如果硬件像素语义无法仅由代码证实，应明确停在候选层级；之后需要有条件的非零输入/实际 RAW 输出对照。不会通过自建一个加减法模型“验证”尚未确认的硅片算法。
