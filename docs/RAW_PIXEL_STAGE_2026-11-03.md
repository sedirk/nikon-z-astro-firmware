# 四路负偏移、0x720、空间表与 NEF 像素的证据边界

日期：2026-11-03，Asia/Shanghai。初代 Nikon Z6 C3.80。接续 [RAW 输出与相邻参数](RAW_OUTPUT_ROUTING_2026-11-03.md)。目标仍为保留暗电流、关闭静态 NEF 写入前的 RAW 校正、消除彩圈。

同日后续：[空间表数据来源与状态条件](RAW_SPATIAL_SOURCE_2026-11-03.md)补齐 864 项浮点输入、原厂转换与缓存、0x1c14 状态发布及不同类型构造；新增 14 组有效用例。本文保留前轮记录，最终保存像素的证据边界不变。

**本轮没有确认这三类参数改变最终保存的 NEF 像素。** 新完成的是原厂完整配置包内的独立参数对照，并找到空间表六个生成系数的另一消费者：`NEFInfo 0x0007` 的 104 字节元数据。这个发现使我们能区分“硬件配置变化”“元数据变化”和仍未观察到的“像素变化”。

17 组隔离用例通过，执行 259 个原厂函数／基本块片段，记录 7,040 次 MMIO 写入。没有修改原厂指令，没有实现假定的像素算法，没有新增 QEMU 运行、生成完整 NEF、刷机或提交 Git。原始升级包、四个解包模块及本地 QEMU 源码的哈希见本轮校验（`analysis/raw-pixel-stage-2026-11-03/verification.json`，本地归档未公开）。

## 1. 对用户优先问题的直接回答

| 候选 | 本轮已验证 | 最终保存像素是否受影响 |
| --- | --- | --- |
| 四路负偏移 | 原厂生成后，在私有 RAM 中单独清零任一槽，仅改变完整配置包对应的 `bank+710/+714` 半字；另三槽与空间表保持原值 | **未验证。** 尚缺硬件输出取样位置、算术及使能语义；不能将清零等同于保留暗电流 |
| `bank+720` | 单独将参数 32466 改为 12345，完整配置中仅 `+720` 改变；不改变本轮 `NEFInfo 0x0007` | **未验证。** 参数生成有上限，仍不能直接命名为像素裁切阈值 |
| 两组 17 项空间表 | 六系数中的 C0、C3 可分别改变第一、第二组；原厂驱动将两表独立上传到 `+1200/+1224` | **未验证。** 同源系数还进入 NEF 元数据；尚无证据把两表命名为硬编码彩圈校正 |

此前 `0x3e1` 还连接源端正数参数与 BlackLevel 元数据。这轮没有同时改动该公共配置，而是分别干预后端参数，以免将多处变化混为一个像素效果。独立干预只用于识别软件依赖，**不是建议真机直接清零这些值**。

## 2. 原厂完整配置包的独立对照

脚本：[probe_pixel_stage.py](../tools/fw/probe_pixel_stage.py)。原厂 ROM 在 Unicorn 中设为只读、可执行；校准、对象、缓存和 MMIO 使用私有人工 RAM。完整执行 `0x100b5716` 构造配置包，再完整执行 `0x100d5c86(driver, packet, 0, 0)`，没有删除包内其他指针。每次调用记录入口、参数、停止位置、基本块、候选内存读取和 MMIO 写入；各段前刷新 Unicorn 翻译缓存。

人工基线：标量 B=300、增益形式参数 G=512、原厂 ROM 所选四个相邻值均为 300；原厂计算得到 `+720=32466`。两表的缓存系数基线为零。所有非零输入均是实验夹具，不是用户相机的校准数据。

| 对照（bank 0、1 各执行一次） | 相对基线改变的最终配置 | 104 字节 `0x0007` 变化 |
| --- | --- | --- |
| 基线 | 无 | 无 |
| 仅清零负偏移槽 0 | `+710: 1ed41ed4 → 00001ed4` | 无 |
| 仅清零负偏移槽 1 | `+710: 1ed41ed4 → 1ed40000` | 无 |
| 仅清零负偏移槽 2 | `+714: 1ed41ed4 → 00001ed4` | 无 |
| 仅清零负偏移槽 3 | `+714: 1ed41ed4 → 1ed40000` | 无 |
| 仅改变 `A+19c` | `+720: 7ed2 → 3039` | 无 |
| 仅置缓存 C0=16 | 第一组 17 个值均变为 1，`+1200..+1220` 的 9 个字改变 | 偏移 `0x2c` 及 CRC 两字节 |
| 仅置缓存 C3=32 | 第二组 17 个值均变为 2，`+1224..+1244` 的 9 个字改变 | 偏移 `0x50` 及 CRC 两字节 |

表中数值及地址偏移为十六进制，B/G/C 输入值及“17 个值”使用十进制。A=owner+394；空间系数到表的换算使用原厂生成器，未用 Python 代替算法。每次完整驱动写入 440 次，16 组共 7,040 次；配置包本身未被驱动改写。

所有对照均保留输入 `+310=60000000`、替换 RAW 输出 `+3ec=62000000`、`+580=1`、`+67c=300`。另外独立执行原厂句柄交换、编码入口前缀、封装与 chunk 3 选择，保持软件接力路径一致。**句柄或输出描述符不变不代表像素不变**：三个假定像素／编码载荷地址 `60000000/62000000/64000000` 故意未映射，没有进行像素读写或完整编码。chunk 描述符中的地址和长度由夹具提供，不是生成的 RAW 文件。

结果：`analysis/raw-pixel-stage-2026-11-03/isolated-stages-v2/result.json`（本地归档，未公开）。其中 1 组验证原厂 NEF profile 0 的 group 15 选择，另外 16 组为上述双 bank 对照。各段为有界、独立进入的原厂代码；没有模拟一次真实硬件完成后的连续拍照。

## 3. 新发现：两表的同源系数进入 NEFInfo 0x0007

恢复的数据流如下。虚线处仍缺硬件证据，不能由软件调用顺序补全。

```text
输入属性／缓存 → 原厂六系数
  ├─ 1019702a → 两组 17 项表 → 打包 → bank+1200/+1224
  │                                      ⋯ 硬件是否作用于 +3ec 的 RAW？
  └─ 10197678 → owner+ff8..1013
                  → 101bb37a → 102899a0 → NEFInfo 子标签 0007

四路负偏移 → bank+710/+714 ────────────────⋯ 同一缺口
相邻参数   → bank+720 ────────────────────⋯ 同一缺口

替换 RAW 句柄 → 原厂 RAW 编码器 → NEF chunk 3（软件联系已恢复）
```

已核实的原厂指令与数据：

1. 静态路径 `100ad6d4..100ad6e8` 将 owner+ff8 作为系数导出目的地。`10197678` 导出两个标志和六个有符号 32 位系数。
2. `101bb37a(owner, dst)` 复制 ROM `11529e7c` 的 96 字节模板，再填入上述标志和系数。`102899a0` 是完整 104 字节标签回调，调用原厂版本指针初始化与获取函数、模板填充和 CRC 函数，输出非人工编造的标签字节。
3. ROM 描述符 `11536da8` 为 tag=7、type=7、callback=`102899a1`（Thumb 指针）。原厂 profile 0/group 15 选择列表为 `[5,6,7,8,9]`，过滤器 `1028d2ea` 返回 1；已在隔离执行中验证选择结果。
4. 外层描述符 `11537538` 为 tag=`c7d5`、callback=`102889d5`。回调原指令保存标签条目指针到写入上下文+48；NEF 写入函数 `1026dcaa..1026dcf0` 使用同一位置补外层偏移、长度，并调用 group 15 写入。这闭合了父标签联系，尚未生成整份 NEF。

| 系数 | owner 字段 | 104 字节标签内偏移 |
| --- | --- | --- |
| C0 | +ffc | +2c |
| C1 | +1000 | +1c |
| C2 | +1004 | +14 |
| C3 | +1008 | +50 |
| C4 | +100c | +40 |
| C5 | +1010 | +38 |

标签前 4 字节版本来自原厂 ROM `11536080`；标志位于 +4/+5a。原厂函数 `101b4b90` 对前 102 字节计算 CRC，写入 +66；与独立 `binascii.crc_hqx(data, 0xffff)` 相符。两组单系数对照还分别验证了系数、硬件表、标签字节和 CRC 的对应关系。

**实际用途：以后比较 NEF，必须将 RAW 样本、元数据和预览分开。** 改变系数可仅凭元数据差异造成整文件哈希变化；解码器也可能使用元数据影响显示。必须检查未经自动黑位扣减、镜头校正或去马赛克的存储 RAW 样本，才可讨论像素效果。

外部命名只作交叉参照：[ExifTool 官方 Nikon.pm](https://raw.githubusercontent.com/exiftool/exiftool/master/lib/Image/ExifTool/Nikon.pm)将同组 `0x0005/0x0006` 分别命名为 DistortionInfo/VignetteInfo；对 `0x0007` 仅有“可能与衍射校正有关”的源码注释，并未确证。**本项目不据此给 0x0007 或两表定名为衍射、色差、暗角或彩圈校正。** 保存的源码（`analysis/raw-pixel-stage-2026-11-03/exiftool-nikon.pm`，本地归档未公开）及抓取时间、URL、SHA-256（`analysis/raw-pixel-stage-2026-11-03/exiftool-nikon.source.json`，本地归档未公开）用于固定这次参照；在线 master 后续可能变化。

## 4. 空间表输入已向上游推进一层

静态路径 `100c24f2` 构造输入属性，request+2e=0 时将 owner+227c 经 `100c0eda` 写入 properties+2c；另一分支从 owner+22fc 经 `100c22ac` 构造缓存相关输入。

`100c0eda` 的有效类型 1 分支复制原对象+44/+46、+48、+49 起八字节、+54 指针、+59/+5a、+5c。其中原对象+5a 进入 properties+45，连接此前发现的 bit 2 条件。这样可继续追条件来源，而不必盲目清空整张表。

owner+227c 的生产者已连接：`1013da98 → 10072714`。后者读取属性 ID `0x1c14`；有效分支通过 `101c2692/101c2658/101c2660` 获取数据，将来源头+10 作为后续参数指针。**0x1c14 的菜单或物理语义尚未确认，不能直接当作“关闭校正”开关。** 相关普通/缓存路径仍需真机条件和实际校准数据验证。

证据：输入构造（`analysis/raw-pixel-stage-2026-11-03/input-builder.txt`，本地归档未公开）、owner 输入生产者（`analysis/raw-pixel-stage-2026-11-03/owner-input.txt`，本地归档未公开）、属性和版本路径（`analysis/raw-pixel-stage-2026-11-03/property-and-version.txt`，本地归档未公开）。宽立即数检索只提供候选；不同对象的相同偏移不自动等同。

## 5. 为什么当前模拟器不能回答像素问题

本轮核对固定的本地模型实现，保存依赖审计、源码摘录与哈希（`analysis/raw-pixel-stage-2026-11-03/model-dependencies.json`，本地归档未公开）。

- `nikon-z6.c` 将 `2038/203c` 配置记录在数组中；记录寄存器不等于实现其像素功能。
- 可选 `nikon-functional-isp.h` 普通事务从 bank 0 RAW 输入读数据，使用明确标为假设的 RGB/NV12 转换向三个传输通道写出；未消费本轮候选的四路负偏移、`+720` 或两张表。
- 此实现对 `+3ec` 的像素写入在 448 字节原地 dummy/drain 复制分支中，不是静态照片 RAW 校正链。
- `nikon-isp-pixels.h` 的色调处理使用模型 geometry 中的 black_level/white_level，不能代替原厂寄存器的语义。

因此，即使补通拍摄等待、保存出模型 NEF，仍不能用候选开关前后像素一致证明真机不受影响，也不能给模型人为加入想象的扣黑／空间增益，再把模拟结果当成破解成功。本轮没有改模型。

## 6. 失败、复现与验收边界

首次 `isolated-stages` 在封装入口 `100b1634` 的 `100b1732` 出现未映射读取：夹具误传了空预览描述符，而原厂函数无条件读其+8。修正为映射的零填充描述符后，`isolated-stages-v2` 全部通过；没有跳过原厂指令、替换返回值或补像素。失败结果与旧脚本（`analysis/raw-pixel-stage-2026-11-03/isolated-stages/result.json`，本地归档未公开）继续保留。

早期 table-inventory 使用了错误的描述符搜索范围，结果为空；v2 修正为实际 NEFInfo 描述符表并验证 tag 5/6/7。探索性线性反汇编可能包含常量池或从宽指令中间开始的记录；报告关键连接优先引用14 段整理后的指令证据（`analysis/raw-pixel-stage-2026-11-03/curated-evidence.txt`，本地归档未公开），保留原字节、字面量地址和静态/动态依据，不把线性解码成功当作全部为代码。

所有正式研究调用的 argv、工作目录、UTC 时间、退出码、stdout/stderr 在命令目录（`analysis/raw-pixel-stage-2026-11-03/commands`，本地归档未公开）。复现需选择尚不存在的输出目录，避免覆盖证据：

```powershell
.\work\re_env\Scripts\python.exe tools/fw/record_research_command.py --record analysis/raw-pixel-stage-replay/command -- .\work\re_env\Scripts\python.exe tools/fw/probe_pixel_stage.py --output analysis/raw-pixel-stage-replay/run
.\work\re_env\Scripts\python.exe tools/fw/verify_pixel_stage.py
```

验证器核对五份固件哈希、模型源码、原指令字节、17 组结果及元数据 CRC、候选寄存器的独立变化、正式命令退出码和文档链接。它验证记录的可核查性，**不验证硅片处理或真实 NEF 像素**。

## 7. 下一步只补决定性缺口

1. 优先寻找能确定 RAW `+3ec` 取样点的硬件依据：实际静态帧的配置、处理前后缓冲与编码输入，或可核实的硬件实现／规格。寄存器相邻、写入先后、同包上传都不能替代此证据。
2. 上游逆向可继续追 `0x1c14`、owner+227c 和 `101c2660` 返回的数据，区分镜头条件、机身校准及缓存来源；以明确两表功能为目的，不扩展成无目标菜单研究。四槽与 `+720` 的配对关系、使能和饱和顺序仍需同时查清。
3. 得到可信硬件输出后，单独变化四槽之一、`+720`、第一表、第二表，并同时比较存储 RAW 样本与 NEF 元数据。暗场验证保留的信号及裁切；多曝光平场验证通道比值和空间台阶。当前 `samples` 无实际 NEF，不能进行该项验收。

现阶段保留暗电流、关闭 RAW 校正、消除彩圈均未达成；没有可刷的天文固件。本轮的价值是独立了候选参数，并排除了把元数据或模拟器缺失功能误当像素证据的路径。
