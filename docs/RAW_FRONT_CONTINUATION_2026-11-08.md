# 2026-11-08 接续：临时前端阶段之后、SPI8 报文与标定装载源

本轮把静态临时阶段之后的调用次序补齐，并新增连通 **标定记录 → 原厂报文 → SPI8 发送** 的路径。原厂目录查询还确认：ID `0x38` 的装载源为 `0x13e80000`，目的地为此前追踪的 `0xc9700000`。这些结果为固定校正和暗信号处理提供了更具体的字段与数据来源。

三个 QEMU 会话分别保存 71、102、82 条观察；第二个包含八组人工非零／空长度对照。实验仍使用既有合成启动、无电子镜头与无卡诊断设置，未增加设备算法或完成事件。**本轮验证层级是原厂控制流、内存和发送数据；保留暗电流、关闭校正与消圈的最终验收仍以保存的 NEF 像素为准。**

证据入口：摘要（`analysis/raw-front-continuation-2026-11-08/evidence-summary.json`，本地归档未公开）、复核结果（`analysis/raw-front-continuation-2026-11-08/verification.json`，本地归档未公开）、命令和输出（`analysis/raw-front-continuation-2026-11-08/commands`，本地归档未公开）、精选原指令（`analysis/raw-front-continuation-2026-11-08/curated-native.txt`，本地归档未公开）。前轮[机身侧前端表](RAW_BODY_FRONT_2026-11-08.md)的非零上传对照继续有效。

## 1. 临时阶段结束后实际执行了什么

此前每点首次命中的观察已升级为选定点的重复断点观察：命中后移除断点、单步原指令、重新设点。控制器对每个外层调用最多重设至 256 条跟踪记录；本轮最大窗口为 48 条，全部未触及上限。保存了每个窗口的起止、数量和控制器源码，不能将此覆盖范围外的执行概括为“从未调用”。

三次会话在 `native-settle` 窗口中一致观察到以下次序：

| 阶段 | 原厂位置／参数 | 观察结果 |
| --- | --- | --- |
| 静态 RAW 前端提交 | `10076a08 → 100bd820` | 同一主 RAW 句柄，像素目的地址 `a448e000`，格式 2、6104×4222、跨度 9168 |
| 临时阶段开始 | `10179d4a` | 即将把 `ctx+84` 从 0 写成 1 |
| 前端操作 | `1011c750` | 依次参数 0、1 |
| 表生成／上传 | `1011dce0 / 1011df8c` 等 | 选中 `cal+293c0` 和 `cal+2dbd0`，正标量和两组表上传 |
| 等待与清除标志 | `10179da4 → da8 → dd4` | 等待返回值 1；`10179dd8` 时 `ctx+84=0` |
| 后续串行配置 | `1011b7bc`、`1011ba4e` | kind 2 → 一份 11 字节报文 → kind 4 的九份报文 → kind 5 |
| 收尾 | `1011c750(2)`，随后 `10179e58` | 返回前最后的 `orrs r0,r4` 两个输入均为 0 |

在清除 `+84` 后直到该窗口结束，重复断点没有记录到第二次正标量／32 组表／144 项表上传。**清除临时标志本身没有伴随一次已观测的“恢复表上传”。** 此结论不把后续硬件行为或其他观察窗口排除在外。

三个会话均保留后端静态处理 `100ae33e`、替换写回 `10106980`、编码 `100af648` 为未命中的观察点；取景阶段的四路负偏移上传单独归类。此次没有新增完整 RAW 扫描，也没有用此前全零缓冲做候选效果比较。

## 2. 新找到的标定报文与选择规则

以下 `cal` 指 `*(c18fa954+14)`，本轮值为 `c9700000`。函数地址、字段偏移和报文字节已恢复；接收器内部寄存器的物理名称尚待定位。

| 路径 | 来源 | 打包／选择规则 |
| --- | --- | --- |
| `1011ba4e(argument)` | `cal+be0d0` 或 `cal+be0e0` 各取 8 字节 | 每次先翻转状态字节 `c18fa954+6`；`argument=0` 才发送 `81 00 db` 加 8 字节；非零参数仍翻转状态，但不发报文 |
| `1011b7bc(kind=2,ctx)` | `cal+bf770 + selector*512`；长度表 `cal+c1b70` | 本轮 selector=1，数据起点 `cal+bf970`；逐项读取 u16 长度，遇零终止 |
| `1011b7bc(kind=4,ctx)` | `ctx+b0..c0` | 生成九份报文，地址字节为 `003d / 0047 / 0055 / 041f / 0424 / 05a6 / 05a8 / 05e1 / 05f7` |
| `1011b7bc(kind=5,ctx)` | `cal+c22b0 + selector*32`；长度表 `cal+c24d0` | 本轮 selector=1，数据起点 `cal+c22d0`；同样按长度表分包 |

kind 的入口由 `1011b7f6` 的 TBB 跳转表选择；kind 2／4／5 的实际目标分别为 `1011b836 / 1011b890 / 1011b9ac`。映射表和上下文决定记录 selector，不把 kind 数值直接命名为用户拍摄模式。

kind 4 的字段关系来自原指令：`b0/b2` 两个 u16 各保留低 12 位装入 `003d`；`b4/b6` 同样装入 `0047`；`c0、bc、bf、ba、bb` 分别进入五份单字节报文；`b8/b9`、`bd/be` 进入最后两份双字节报文。当前原状态这些字段为零，发送数据见事件文件。这里的 `003d` 是报文的地址字节，不能因数值相同就认作 NEF 的 BlackLevel 标签。

**对补丁思路的影响：`1011ba4e(1)` 不是一个已确认的校正关闭接口。** 它会改变下一次取哪份标定记录，跳过一次发送与禁用硬件处理应分开研究。两份 8 字节记录也尚未命名为四通道黑电平。

## 3. 从报文字节到 SPI8 日志的交叉核对

已连接的原厂路径为：

```text
1011ba4e 或 1011b7bc
  → 101228c2(data, lengths)
  → 1017e524(data, length)
  → 1017e57c 调用 100d2a2a(channel, descriptor)
  → 100684f8
  → SPI8 FIFO（模型映射 2c0a0800）
```

`101228c2` 顺序发送非零长度的包；发送返回非零则停止。`1017e524` 操作 GPIO 控制句柄，将每个字节扩成 u16 暂存于 `c29a3f74`，以最多 192 字节一批提交。观察到串行上下文 `c18fa9bc` 的通道为 8，提交描述符中发送／接收计数相等，接收地址为零。

第二、第三次会话共核对 26 组“报文字节—提交描述符—u16 暂存内容”。三个会话各自日志末尾的 10／16／10 包，与观察窗口捕获的报文逐字节、按次序一致。日志中的非零人工字节也与输入完全对应，证据已超出单纯观察函数入口。

模型边界由固定源码确认：nikon-z6.c（`work/src/z6-qemu-419a1f2a91a1f2d3a0209027c29606475f7fe26f/qemu/nikon-z6.c`，本地归档未公开） 的 `nikon_panel_access / nikon_panel_complete` 将 SPI8 作为未连接真实设备的收发端，记录发送字，并以高电平形成接收值。**日志证明原厂代码送入了该发送路径；它没有提供传感器实际响应或像素校正结果。** 本轮未修改这部分实现。

## 5. ID 0x38 的装载源和装载链

第三次会话在原厂目录查询 `101f620e(0x38,out)` 中取得返回值 1，输出如下：

| 输出字段 | 运行值 | 含义依据 |
| --- | --- | --- |
| +0 | `c9700000` | 目录 +8，RAM 目的地 |
| +4 | `13e80000` | storage 项 +0，装载源 |
| +8 | 0 | 目录 +4，偏移字段 |
| +c | `168000` | 目录 +c，数据长度 |
| +10 | `180000` | storage 项 +8，区域长度 |

目录 `c1881298+14 = 0x18` 选择存储条目 `c1880c4c`。该条目与原 ROM `11f15a20` 的 44 字节逐字节相同，开头五个 u32 为：`13e80000, 0, 180000, 17fffc, 1`。目录模板位于 `11f1606c`。

静态装载链为：

```text
101b045e(ID) → 101b03f2(directory,storage)
  → 10091882：检查条件，再按描述符 +20 的值选择传输
  → 101c4f62(destination,source,length)
  → 101c4e98：构造 count=length-1、source、destination 等字段
  → 10068d3c：将这些字段和控制位写入传输驱动寄存器
```

最后两层呈现 DMA 传输描述符与寄存器设置。此次动态执行的是只查询描述符的 `101f620e`；整块加载函数未另行调用，加载成功也没有由此推定。探索时读到的 `10091246` 是另一条含擦除／写入调用的路径，只作为静态材料留档。

当前主程序映像范围为 `[10020000,1201367a)`，因此源 `13e80000` 位于该主映像之外。这解释了为什么应继续研究资源区和内容装载，而不是只在主程序附近寻找完整数值表。是否含逐机独有校准、型号共用参数或两者混合，仍由数据内容和写入来源决定；本轮没有取得真实机身该区的内容。上游现有诊断文件也记录过这个源地址，本轮的新增证据是原 ROM 表项、运行时目录查询，以及到传输驱动的静态连接。

## 6. 与暗电流、彩圈和最终 NEF 的关系

| 主线 | 本轮新增事实 | 下一项有用验证 |
| --- | --- | --- |
| 四路负偏移与 `0x720` | 共同上游标定块的装载源已确定；与 SPI 报文、前端表分别记录 | 沿现有输入 `bank+310`、写回 `+3ec` 与编码句柄，定位真实处理和采样位置 |
| 固定 32 组表／144 项表 | 临时标志清除之后，在重复观察窗口内没有第二次表上传 | 追启用位、硬件采样时序与固定表字段；保留默认沿用旧表的问题 |
| 新 SPI8 标定路径 | 两份 8 字节记录、两种长度表及九份上下文报文的发送规则已连通 | 优先追 `ctx+b0..c0` 的实际写入者、`cal+be0d0/e0` 的其他消费者和条件选择，确定是否涉及偏置、通道缩放或读出配置 |
| 实际数据来源 | ID 0x38 → storage 0x18 → 源 `13e80000`，目录查询返回具体范围 | 查资源区内容与写入来源，区分逐机与共用数据；避免把模型的零标定外推为真机状态 |

“SPI8 参数可能作用于读出前端”“固定表可能参与彩圈”“8 字节可能含通道参数”均列为待检验假设，尚未据此命名算法或制作禁用补丁。普通 257 项暗角与旧两组 17 项表保留原结论，不重新混为同一个校正。
