## 新的运行时证据

### 配置接口确实改变了预期字段

| 控制器调用 | 观察地址 | 调用前 → 调用后 |
| --- | --- | --- |
| `0x101cb766(0x3dc, 1)` | `0xc20aaba4` | `00 → 01` |
| `0x101cb766(0x3dd, 1)` | `0xc20aaba5` | `00 → 01` |
| `0x101cb734(0x29e)` | `0xc20aaa66` | 保持 `00`（读取） |
| `0x101cb766(0x29e, 1)` | `0xc20aaa66` | `00 → 01` |
| `0x10122852(0)` | `0xc18fa970` | 32 位值 `0x80400000 → 0` |

最后一项尤其需要注意：完整模型启动时该字段并非简单的布尔值 1，而是看起来像地址的 `0x80400000`。本轮确认了清零行为，尚未证明其指向内容的物理用途。不能直接称为已经取消某种真实传感器校准。

通道 8 回调表在运行时存在 `0x101f61b3`（Thumb 指针），不同于此前隔离实验中人为保持空回调列表的条件。完整回调语义仍待追踪。

### 原厂执行路径到达空列表分支

在单独的带断点会话中，仅在上游 `call_fixture` 调用窗口观察以下地址：

- `0x100bc150 → 0x100bc18e → 0x100bc204`：各命中一次，位于 `capture_start` / `0x10525a70` 调用期间。取景模型中实际进入 `0x29e == 1` 的空列表分支。
- 三个点的 R6 均为 `0x34bc8400`，源参数 R10 为 `0x80660000`；在出口 R4/R1 为 `0xe400`，R0 为 `0xffffffff`，与此前静态和隔离执行结果一致。
- `0x100bc5b0 → 0x100bc5d6`：各命中七次，前者 R0 为索引 `0x29e`，后者 R0 为 1。这里的命中次数只是本次有限观察窗口，不是全系统调用次数。

简化事件表在 `analysis/post-reboot-2026-11-02/consumer_trace_summary.json`，完整寄存器与部分内存在 `shooting-trace/session/actions.jsonl`。

随后在独立的 `table-observation` 会话中，在 `0x100bc204` 断点读取了实际 R6 缓冲区的 `0x39000` 字节：共 231,648 个零字节、1,824 个 `ff` 字节，每 512 字节块以一个 `0xffffffff` 开始，共 456 个终止标记，与隔离实验的布局完全一致。文件为 `table-observation/table-0.bin`，SHA-256 `319515232852d0355a98777354e6c11fb02cec858197e87317dd63f8dc6876c0`。这里的缓冲来自模拟器中的固件执行，不是真实传感器样本。

待验证线索：输入参数 `0x80660000` 与上述原始字段值 `0x80400000` 相差 `0x260000`，处于启动表记录的 `0x80400000` 起始、长 `0x340000` 的清零区域内。这一地址关系可以指导下一步查找数据加载路径，尚不能证明标定类型或两者的运行时依赖。

这证明相关控制流在本机完整 QEMU 会话中实际执行。尚未证明列表的物理用途、静态 NEF 写入关系、暗电流保留或彩圈消除；原厂静态照片保存和真机对照仍未完成。
