# 系数接收写入、RAW 完成事件与写回位置

日期：2026-11-03，Asia/Shanghai。初代 Nikon Z6 C3.80。接续[空间表来源研究](RAW_SPATIAL_SOURCE_2026-11-03.md)，优先追踪实际写入者和 RAW 写回位置，服务于保留暗电流、关闭静态 NEF 前 RAW 校正、消除彩圈。

**本轮找到了空间系数的接收目的地配置与发布者，以及 RAW 状态寄存器、完成事件、句柄交换之间的软件联系。仍未确认四路负偏移、bank+0x720、两组空间表改变最终保存的 NEF 像素。** 接收 DMA 和 ISP 的真实内存写入没有在本轮发生；不能把寄存器设置或人工完成状态当成硬件像素证据。

新增有效对照共 **23 组、267 次原厂函数／有界片段执行**：接收与发布 8 组／228 段，RAW 完成与交换 15 组／39 段。原厂 ROM 在独立进程中只读执行，实验数据全部在私有 RAM。未修改原固件、未运行新的 QEMU 拍摄、未制作补丁、未刷机。本轮没有完整 NEF；此前对最终像素的证据限制继续有效。

## 1. 两组空间表：接收缓冲与发布者已经找到

以下 slot 编号采用十进制，地址及命令字节采用十六进制。

| slot | 命令字节 | 请求长度 | 发送缓冲 | 接收缓冲 0 | 接收缓冲 1 |
| --- | --- | --- | --- | --- | --- |
| 15 | `24 10` | `d8c`，3468 字节 | `c280eac0` | `c2813400` | `c28141c0` |
| 17 | `24 12` | `d8c`，3468 字节 | `c281a740` | `c281b500` | `c281c2c0` |

这些来自 ROM `11f70404+slot*24` 的原厂描述符，启动时复制到 `D=c18db630+slot*24`。`D+8` 是传输请求的发送地址，`D+0c/+10` 是交替使用的两个接收地址。此前不能把第三个缓冲简单当作接收数据的 CPU 复制源。

原厂索引初始化 `100c3490..100c34aa` 设置 88 个读取计数为 0、写入计数为 1。读取索引存放在 `c2813140+4*slot`，写入索引在 `c28132a0+4*slot`，均取最低位选缓冲。`100c3648` 取得当前读取缓冲，`100c3590` 取得待写缓冲。

已恢复的配置路径：

```text
10131dc8：slot 分派（TBB 表已单独按数据读取）
  slot15 → 1007b3c0 ┐
  slot17 → 1007b3d8 ┴→ 1007b1e2 → 1007b0bc：构造 40h 字节请求
                         +10 = 发送地址
                         +14 = 未发布的接收地址
                         +0a/+0c = 传输长度
  → 100cb158 → 100cb0a8：请求转换
  → 1008c6a0：复制请求到 c29a42f0
  → 1008c754..1008c772：设置传输描述符 c29a42c8
  → 100d2a2a 的 mode=4 分支 → 100d2d1a
  → 100d27be：构造接收 DMA 参数
  → 10068b06：写 DMA 的控制、来源与目的地址寄存器
```

另一传输阶段 `1008c812..1008c82c` 使用 `c29a5700` 作为发送地址，但接收目的地仍来自请求 `+14`。这两段的存在不等于本轮完整执行了异步传输状态机。

在接收设置中，`100d27be` 把传输描述符 `+4` 放入 DMA 参数 `+14`，把传输数量减一写入 `+4`。原厂上层将 `d8c` 右移一位，得到 1734，DMA 数量字段为 1733。`1006860a` 从串行设备句柄取得接收端地址。最终 `10068b06` 的 `PC=10068b6a/10068b72` 分别写来源／目的寄存器。

**证据边界：已找到的是原厂接收写入配置。** 本轮串行设备句柄、DMA 通道及寄存器指针表是人工夹具，寄存器指向普通私有 RAM；没有识别并运行真实物理端口，也没有从镜头或机身取得通信数据。LensInfo 关联和接收命令使外部通信来源成为更具体的候选，仍不能给这两组系数直接冠以“镜头畸变”“暗角”或“机身彩圈校正”的名称。

### 成功发布才改变后续空间表

`1008bd92` 检查接收帧首字节 `55` 和字节和校验；校验和失败时设置错误码 8。高层回调 `10131d64` 仅当完成数据 byte 0 为 **1** 时调用 `100c34be(slot)`，使读取／写入计数各加一，切换当前缓冲；失败不切换。

用例覆盖 slot 15/17、初始读取索引 0/1、成功／坏校验和，共 8 种。人工旧帧生成六系数 `[16,0,0,32,0,0]`，新帧生成 `[48,0,0,96,0,0]`；非零值按原厂浮点输入布局放入 864 项源数据。

| 阶段 | 原厂生成的第一组 17 项 | 第二组 17 项 |
| --- | --- | --- |
| 新数据已放入待写缓冲、尚未发布 | 全为 1 | 全为 2 |
| 坏校验和，并独立调用失败回调 | 全为 1 | 全为 2 |
| 校验通过，并独立调用成功回调 | 全为 3 | 全为 6 |

每次通过原厂 `1015e0a0 → 101c2660 → 10072714 → 100c0eda → 10196fe4 → 10197500 → 101975be → 10197678` 生成参数，未以 Python 模拟系数算法。源帧前后字节保持不变。输入仍为人工数据；验证器与回调是分别进入的原厂函数，**不是校验通过后自动完成了一次真实通信**。

还确认一个原厂初始化片段 `10075128..1007513a` 通过 `101c1e58` 设置 `S+0b=12、S+0c=20`，因此前轮浮点转换所用的 20 不再只有人工选值依据；尚未证明它在所有状态下始终如此。状态写入函数 `1016110e(r0,r1)` 分别写 `S+3/S+6`，调用者线索已保存，数值的物理含义仍未命名。`S=c18d4090`。

## 2. RAW 写回：目的地址已知，实际像素仍未观测

前轮确认的替换 RAW 地址链保持有效：

```text
照片对象 +1fc 的替换句柄
  → 请求 +1a8 → 100b36f0 → packet+20 指向的参数块
  → 100d5c86 → 10106980
       PC 1010698c：像素目的地址 → bank+3ec
       PC 10106996：行跨度       → bank+3f0
     10106974：格式              → bank+3e8

bank = 20380000 + (驱动对象 byte+4 << 18)
```

这些是 CPU 对写回目的地址的配置指令，**不是 CPU 把处理后的像素写入那个缓冲的指令**。当前证据把待确认的数据写入者限定到处理硬件一侧，但没有证明 `+710/+714`、`+720`、`+1200/+1224` 的算术发生在 `+3ec` 输出取样点之前。

### 原厂启动与完成事件

本轮补齐了以下可设观测点的链条：

| 层级 | 原厂位置与行为 | 本轮证据 |
| --- | --- | --- |
| 启动 | `10105eae(driver)` 向所选 bank 的 `+10`、`+08` 各写 1 | 私有 MMIO 中完整执行 |
| 状态读取 | bank 0 的 `101058ac`、bank 1 的 `10105870` 读取 `bank+24`，写回所读值，再调用登记回调 | 原厂函数执行；状态值由夹具提供；没有实现写一清零 |
| 中断登记 | `101058e4` 将上述处理入口登记到编号 `63h/64h`；`1010615a` 设置驱动回调 | 登记关系来自反汇编，驱动回调设置已执行 |
| 常规完成分支 | 回调 `100d56d6/100d5684` 在普通状态、状态位 1 置位时请求相应事件位 1 | 执行到 `10105264` 入口即停，未实际发送 OS 事件 |
| 异常／收尾分支 | 同一回调能分别请求事件 `100h/80h` | 单独用例验证，不能把所有事件均视为正常帧完成 |
| 等待 | `100d61e2 → 100d57a6` 等待并检查事件；后续回调进入 `100d67d8` | 等待关系静态恢复，没有强制等待成功 |

静态 instance=1 的提交仍为 `100b4c78 → 100d67f4 → 100d639e → c1d8833c`，工作函数为 **`100d62e4`**。相邻 `100d63f0` 属于另一队列，不能混用。原厂初始化 `100d64ec` 明确这两个对应关系。

最终回调 `100d67d8` 对输入消息 `42170801 / 4217080b / 42170806` 分别写全局 byte+1 为 `0 / 2 / 1`，随后都请求事件位 8。阻塞调用还检查等待结果及该状态字节；只看到事件位 8 也不足以证明成功。本轮三组独立回调测试停在 OS 接口前。

### 句柄交换本身不是写回成功证明

`100ae3ce` 调用 `100b4c78` 后，`100ae3d2` 立即把另一个字段读入 r0，覆盖返回值。后续交换检查请求 `+1a8` 是否非零，没有直接检查这次调用返回值。

从 `100ae3d2` 独立进入，以人工前次返回值 0/1、替换输出存在／不存在组成 4 组对照，停在 `100ae438`：两种返回值都在有替换句柄时交换照片对象 `+1f8/+1fc`，无替换句柄时均不交换。**这只验证该局部控制流，不证明真实失败会一路保存文件，也不代表相机存在已验证故障。** 实验没有执行前面的硬件等待。

同时恢复了 `owner+1ac8` 的直接来源：`10106402 → 10108976` 读取所选 `bank+118`，暂存到 `c180b6e4/c180b6e8`，`100b555a → 100d68aa/100d68b2` 取得这些值，写入 owner。该字段的单位和物理意义未定，不能把它当作实际写入像素数、文件长度或缓冲校验结果。人工 `abc001/abc002` 只用于区分两 bank 的来源。

原厂 `1010699a` 还读取 `bank+3f4/+3f8/+3fc`，已保存反汇编；有限的直接 BL 搜索没有找到调用者，不等于不可达，也没有据此命名这些字段。

## 3. 对三个优先候选的当前结论

| 候选 | 已验证事实 | 仍缺的决定性证据 |
| --- | --- | --- |
| 四路负偏移 | 原厂计算、独立槽位变化、完整包上传到 `+710/+714`；与 `0x3e1`、源端参数和 BlackLevel 的联系见前轮 | 硬件算术、使能及相对 RAW 输出取样点的位置；真实暗场是否裁切、被扣减或过滤 |
| `bank+720` | 原厂生成及独立上传已验证 | 上限参数是否真正限制保存像素；不能由参数限幅推断像素裁切 |
| 两组空间表 | 本轮新增接收目的地配置、双缓冲发布、成功／失败到普通表生成的证据；此前上传及同源元数据联系保留 | 真实通信数据与类型、硬件如何消费表、是否作用于保存像素及是否是彩圈来源 |

没有把这三项改成“已关闭”，没有把表值清零或设置 0x3e1 当作补丁方案。元数据变化、描述符变化、事件发生、模型输出一致，均不能替代存储 RAW 样本的对照。

本地固定 QEMU 的功能 ISP 源码（`work/src/z6-qemu-419a1f2a91a1f2d3a0209027c29606475f7fe26f/qemu/nikon-functional-isp.h`，本地归档未公开）中，`+3ec` 的显式 448 字节写入属于独立 dummy/drain 分支；该分支自行置状态位 1，并明确不代表新图像。结合本轮事件链，这进一步说明“模型发出了完成事件”不能证明静态 RAW 校正完成。模型未实现本项目候选参数的真实像素算法；本轮保持源码不变。

## 5. 下一步直接围绕像素证据

优先使用已找到的 `+3ec` 目的地、`bank+24` 状态、原厂回调及编码输入位置，取得**同一静态处理请求**的真实输入／输出缓冲和配置。分别记录地址、尺寸、行跨度、内容、完成状态；检查是否发生有效像素写入后再追编码与 NEF chunk 3。不能仅凭句柄交换验收。

在此基础上对四个偏移槽、`+720`、两张表逐项做单变量对照，比较原始样本而非整文件哈希。缺少真实写回或可靠硬件实现时，继续查硬件输出取样点和独立使能证据；不要给模型自行添加假定的扣黑、钳位或空间增益并用它“证明”补丁。

系数来源方面已不需要重找 slot15/17 的轮换发布者；剩下的是物理端口、真实帧内容、`S+3/S+6` 状态含义及实际静态更新时机。只有证实它与 RAW 保存或彩圈有关后，才提高其补丁优先级。原始固件及逐机标定继续保留。
