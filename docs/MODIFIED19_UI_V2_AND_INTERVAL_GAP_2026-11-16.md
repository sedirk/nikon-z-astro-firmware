## 2. 问题 2：原厂 30" + 间隔拍摄 Bug 根因证明与「曝光后间隔」统一改造

### 2.1 三大核心机制与根因数学证明
通过对 `CaptureStateControlService.c` (`0x101FC000..0x10207000`) 的完整逆向与 Unicorn 仿真，查明了全部现象的精确根因：

1. **为什么原厂 `30"` 设 `31s` 间隔会多等 ~31s，而我们的 `60"` 设 `61s` 间隔却完全正常？**
   - 尼康原厂显示的 **`"30\""`** 档位（`tv_s24 = -120`，即 $-5.0\text{ EV}$），底层硬件快门定时器按 $2^5$ 秒计算，实际曝光时间为 **`32,000,000 µs = 32.000 秒`**！加上快门闭合与读出耗时（约 `0.25s`），第 1 张照片实际在 **`t ≈ 32.25s`** 才完成并回调 `0x102065A8`。
   - 相反，我们在 `z6_m600_core.py` 中注入的扩展快门（`60"`, `90"`, `120"`, `300"`, `600"`）写入的是**精确十进制秒数**（例如 `60"` = **`60,000,000 µs = 60.000 秒`**，而非 $2^6 = 64\text{s}$）。
   - 原厂间隔拍摄状态机（对象 `A = 0xC2376340`）在 `0x101FF380` 中采用**刚性起点网格**（`next_target = old_target + interval_ms`）：
     - 当使用扩展快门 **`60"` + `61s` 间隔**：第 1 张在 `60.25s` 结束，早于 `61.0s` 目标点 `0.75s`，`0x101FF308` 判定未超时，等待 `0.75s` 后在 `61.0s` 准时触发第 2 张。
     - 当使用原厂 **`30"`（实为 `32.0s`！）+ `31s` 间隔**：第 1 张在 `31.0s` 时**仍在曝光中**，直到 `32.25s` 才结束！此时 `0x101FF380` 将目标点推进到 `31.0s`，`0x101FF308(now=32250, target=31000)` 返回 `0`（已超时 `1.25s`），随即跳入 `0x101FF3E4` 追赶循环：调用 `0x101FEDBA` **白白扣掉 1 次剩余拍摄计数**，并将下一次目标时间再加 `31s` 推迟至 **`62.0s`**！相机从 `32.25s` 一直干等到 `62.0s`（**曝光结束后等待 `29.75s ≈ 30~31s`**），且总拍摄张数还会少一半！

2. **为什么原厂 `30"` + `1s` 间隔拍 `32`（或 `34`）张最终只拍 1~2 张？**
   - 第 1 张开始曝光时（`0x10200D98`），固件取消 `8s` 对焦超时看门狗并将剩余张数 `[A+8]` 减 1。
   - 第 1 张 `32.25s` 曝光结束回调 `0x102065A8 -> 0x101FF380` 时，由于 `[A+0x34]`（间隔优先）默认为 `0`，代码进入 `0x101FF3E4..0x101FF40E` 循环：每落后 `1,000 ms` 就调用一次 `0x101FEDBA` 扣减 `[A+8]` 并累加 `1,000 ms`，在单次曝光结束瞬间一次性吞掉 31~32 次快门计数，导致仅拍 1~2 张便判定 `[A+8] == 0` 提前结束！

### 2.2 外科手术级单点修复 (`0x101FF392`, 4 字节)
对比固件内尼康原厂「焦距变化拍摄 (`Focus Shift`, 对象 `C = 0xC23763F8`)」在 `0x10206A3E..0x10206A58` 的曝光后间隔实现：
- `0x101FF380(r0=now_lo, r1=now_hi)` 的全部 3 个调用点（`0x102065DE` 正常曝光完成、`0x10206444` 释放忙跳过、`0x102069FC` 对焦超时跳过）均已传入 `0x101FC616()` 获取的当前完成时间戳 `now_ms`，且函数序言 `0x101FF386..0x101FF388` 已将其保存在 `(r6, r7)` 中。
- 将 `0x101FF392` 处的 4 字节指令：
  - **修改前 (`d4e90420`)**: `ldrd r2, r0, [r4, #0x10]` （读取上一张计划起点 `old_target`）
  - **修改后 (`32463846`)**: `mov r2, r6; mov r0, r7` （读取当前快门完成时刻 `now_ms`，不改变标志位，后续 `adds` / `mov r2, ip` / `adc.w` 完整保留 64 位进位）
- **修复效果**：
  1. 下一张目标时间统一变为 `[A+0x10] = now_ms + interval_ms`（即**快门彻底结束后、下一张开始前的纯间隔时间**）。
  2. 因菜单最小间隔为 `0.5s` (`500 ms`)，`now_ms + interval_ms` 恒在未来 `>= 500 ms`，永不误入 `0x101FF3E4` 吞张数循环。
  3. 多张连拍组（`间隔数 × 每次拍摄张数 > 1`）由前序 `0x10206590` 取模分流，组内连拍依旧零延迟连续触发，整组拍完后精准等待 `interval_ms`。
  4. `0x101FF3C8` 比较的 `[0xC18B8718]` 经证实为 2099 年全局 RTC 上限而非序列预估结束时间，总耗时拉长绝不会触发提前终止；且帧间屏幕倒计时（`0x101FC556` 读取 `[A+0x10]`）完全精准。
  5. 「间隔拍摄短片 (`Time-Lapse Movie`, 对象 `B = 0xC23763B0` / `0x101FF206`)」未做任何改动，保留原厂总时长控制。
