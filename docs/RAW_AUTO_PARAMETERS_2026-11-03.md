# 自动参数来源、缓存与替代构造路径

2026-11-03，Asia/Shanghai；初代 Nikon Z6 C3.80。承接 [RAW 目标定位](RAW_TARGET_MAP_2026-11-03.md)，继续服务于保留暗电流、关闭静态 NEF 写入前校正、消除彩圈。原固件保持原哈希；所有动态实验使用内存映像或已有 Linux 副本，无刷写、无可刷补丁、无 Git 提交。

## 对最终目标有用的结论

1. **`0x29c` 不是已经确认的暗电流开关。** 其自动计算函数使用外部属性、标定字段和定点多项式；本函数没有遍历 RAW 像素或暗区统计的代码。尚未排除上游或 ISP 中其他黑位处理，也没有确认该寄存器对硅片像素的运算。
2. **缓存影响已从静态推测升级为原厂函数动态验证。** 配置改为 1 后，静态参数复用仍带入人为设置的非零旧缓存；执行原厂参数清零分支后，再复用才得到零。
3. **还有不读取 `0x29c` 的构造分支。** 标定对象 `+0x1a4=1` 时，包装函数选择 `0x101146f4`，从另一标定对象复制四槽。12 组隔离实验在配置 0/1 下得到相同的非零槽值。其他控制字段及硬件语义未确认，这不是该分支在真机实际启用的证明。
4. **“静态拍摄调用了函数”不等于“函数修改了 NEF 像素”。** 已建立调用联系，但仍需分清主图像处理与 AF／统计旁路。附近服务代码有明确的 `PdAf` 数据导出路径；这提高了对路径用途的核查优先级，不能只靠字符串就把四槽命名为 PDAF 修复。

本轮没有定位到独立的全局黑位扣减／裁切或空间颜色增益开关，没有暗电流保留或彩圈消除结果。后续首要任务是绑定该处理的实际输入、输出与静态 NEF 编码输入，而非继续扩大参数扫描或修复模拟器收尾。

## 1. 自动输入来自哪里

正常构造器 `0x101142de` 在 `0x10114530–0x101145b0` 准备四个 32 位数，传给 `0x10114136`，由它调用 `0x1011308c`。

| 输入 | 已核实的来源 | 尚未恢复的含义 |
| --- | --- | --- |
| 第 0 个字 | `0x101b2a74` 的属性结果经转换，或默认 `0x80`；自动函数将其上限设为 `0x800` | 物理名称及单位，不直接命名为 ISO、光圈或温度 |
| 第 1–3 个字 | `0x101b2a9a` 按 `0xc18844e8` 的类型分派；类型 0/2 使用默认 `[0x3e00,0,0]` | 标量参考量和多项式系数的物理单位 |
| 标定对象 | `0x101149b4 → 0x10184c62`，地址来自 ID `0x25`；`+0x400` 子对象供自动计算使用 | 真实机身标定内容，本模型对应字段为零 |
| 额外缩放条件 | `0x101b2b14`，类型 1/3 分别读取属性 `0x1019/0x400b` | 属性物理含义；非零标定下该分支未做交叉实验 |

类型 1 的系数读取器 `0x10186484` 经 `0x101c2658 → 0x1015d2f6` 读取五个属性。ROM 启动复制表和属性分发表分别核对如下：

| 属性 | 分发表分支 | 原厂读取函数 | 第 7 类缓存包的半字偏移 |
| --- | --- | --- | --- |
| `0x3076` | `0x1015ca54` | `0x10078c64` | `+0x11` |
| `0x3079` | `0x1015ca6c` | `0x10078df2` | `+0x1f` |
| `0x307a` | `0x1015ca74` | `0x10078dd0` | `+0x1d` |
| `0x3072` | `0x1015ca34` | `0x1007933a` | `+0x5f` |
| `0x3073` | `0x1015ca3c` | `0x10079310` | `+0x5d` |

`0x100c3648(7)` 从双缓冲描述符选择源包；这里读取的是按属性分派的小型缓存字段，未发现本函数读取主 RAW 像素缓冲的证据。`0x3076` 经 `0x101b15d0` 转换：有效非零值参与 `0x4e2000 / signed16(value)`，零值使用 `0x4e2000`，`0x7fff` 走无有效输出分支；另外两项系数来自属性的有符号 16 位值。

同一属性服务区域的断言使用 `LensInfo.c` 文件名，另有 AF/PdAf 服务线索，支持“镜头属性／AF 相关补偿”的工作假设。**尚未恢复协议字段名，不将倒数量、尺度或多项式自动命名为出瞳、焦距或颜色阴影。** 类型 3 路径读取 `0x6000`，细分转换未验证。

完整辅助启动中，早期类型 1 曾给出 `[128, 0x4e2000, 0, 0]`；随后无镜头 fixture 下类型变为 0，自动函数输入为 `[128, 0x3e00, 0, 0]`。观察到的五次自动计算均返回零，且标定字段为零。这只能解释本次模拟会话，不能推论真实机身或望远镜拍摄时的输出。

## 2. 自动计算恢复到什么程度

`0x1011300e(x, coefficients, output)` 是原厂定点多项式。实验域限定 `x=0/65536/250000/1000000`，系数为脚本列出的四组，避免把较大输入的移位溢出行为外推为理想数学公式。该域内按有符号 64 位回绕并向零取整，可写为：

```text
N = c × 2^32 + a × x^2 + b × x × 2^18
output = trunc(trunc(signed64(N) / 65536) / 65536)
```

自动函数 `0x1011308c` 用标定 `+0x1bc/+0x1c0` 的平方作为两次多项式输入，结合原始常量项形成比较区间。选择字节决定参考值来自标定 `+0x1ac/+0x1b0/+0x1b4`；参考值在该区间内时返回零，区间外继续计算。后段包含整数除法、三次项、限幅和归一化，再乘以 ROM 模式系数。

模式系数表 `0xc1884d53` 的启动值是 `[1,1,1,1,1,3,1,1,1]`；原厂查表函数对超出 0–8 的无符号索引返回零。27 组人工自动参数组合验证了内部、外部参考值及 mode 0/5/9：同输入 mode 5 输出是 mode 0 的三倍，mode 9 为零。随后分别经 `0x29c=0/1` 执行原厂四槽构造，确认计算、编码、清零与缓存写入。

这些数值是**参数而非 RAW 像素**。例如人工输入组合得到 `-103` 或 `745`，只用于核对整数运算，不能换算成相机电子数、DN、暗电流量或图像改善幅度。

在独立 QEMU 会话中，4 组多项式与 6 组自动函数结果和 Unicorn 完全相同。实际执行的仍是原厂函数，未换成 Python 算法；QEMU 中临时更改的标定字段、外部类型及选择字节全部记录并恢复。两引擎一致仍不证明硬件像素语义。

## 3. 缓存实验证明修改时机不可忽略

保留原生无卡静态请求作为观察基线，随后在可丢弃 QEMU 会话中直接调用 `0x10114bb2`。沿用基线取得的 20 字节请求，只改变选择字节和明确列出的 RAM 字段。

12 组实验为：配置 0/1 × 缓存 `0x155/0x3ff` × 选择字节 0/1/2。每组都把缓存值写入相应槽，其余槽为零；配置为 1 也不改变这个结果。

再执行以下受控顺序：

```text
缓存设为 0x155，配置设为 1
  → 原厂 0x10114136 的提前返回分支：缓存及四槽清零
  → 原厂 0x10114bb2：四槽仍为零
```

实验使用主动诊断调用和人工缓存，不是正常真机拍摄。原缓存及配置字节在退出前恢复，函数其他状态变化随整台模拟机退出丢弃。验证的是代码依赖关系，尚未找到所有正常刷新事件，也未形成补丁。

## 4. 替代路径进一步限制 `0x29c` 的覆盖范围

包装器 `0x10114aca` 读取标定 `+0x1a4`：等于 1 时，跳到 `0x10114ba6` 调用 `0x101146f4`，绕开正常的 `0x10114136`。

替代构造器从上下文 `+0x38` 指向的对象复制 `+0xbc/+0xb8/+0xc0/+0xc4` 到输出 `+0x62/+0x64/+0x66/+0x68`。12 组原厂函数隔离执行覆盖配置 0/1、mode 0/2/5、选择字节 0/2，槽值均为人工源值 `[0x21,0x12,0x33,0x44]`，没有读取配置函数，也没有刷新缓存 `+0x1c`。

这里只直接运行了替代构造器，包装器选择条件来自反汇编；未模拟所有上游状态。其他控制字段仍按人工初值，不能将“参数槽非零”解读成“硬件实际执行了校正”。但已足以否定“改 `0x29c` 就能使所有构造路径的四槽恒为零”的说法。

## 5. AF／主图像作用范围仍需查清

ASCII 搜索找到 `A:\PdAf%03d.bin`；代码 `0x100a0ea0` 用 PC 相对地址引用该格式字符串，把状态对象 `+0x12c` 指针及 `0x22cc00` 长度交给导出函数。这是服务代码存在 PdAf 数据导出路径的直接证据。

它不能单凭邻近地址证明 `0x2006b388/38c/390` 只处理 AF 数据，或证明一定修复了主 RAW 的 PDAF 像素。`VIGNETTE CTRL` 也是搜索命中，但没有建立与硬编码彩圈校正的数据流联系，本轮不将其列为定位成果。

下一步先建立 `0x2006b3xx` 的像素输入、输出与静态主 RAW 缓冲的联系，区分主图像、AF／统计及预览。随后独立寻找黑位扣减、负值裁切和二维颜色增益的生产者／提交者；不要继续以 `0x29c` 的整数公式精度作为最终目标进度。
