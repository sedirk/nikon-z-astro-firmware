# 2026-11-08：独立暗角曲线、控制分支与 NEF 信息

本轮找到并运行了一条**独立的 257 项暗角参数链**：原厂函数生成曲线和系数，曲线进入处理驱动的表区，系数进入 NEFInfo `0x0006`。原厂中性分支把曲线设为常数 1024；另一控制分支可以保留系数，同时上传中性表并改变一个硬件控制字节。这使“哪条支线、怎样控制、上传到哪里”的范围进一步缩小。

目标继续是保留暗电流、关闭静态 NEF 写入前的 RAW 校正、消除硬编码彩圈。本轮成果属于**原厂参数、控制流及上传配置的验证**。暗角支线与造成彩圈的机身固定校正之间的关系，以及它在真实 RAW 写回取样点之前还是之后，作为后续验证项保留。四路负偏移、`0x720`、旧两组 17 项空间表继续独立追踪。

最终有效实验为 **15 组、80 段原厂代码执行、43,461 次 MMIO 地址对应的私有 RAM 写入**；26 段精选反汇编逐条与原 ROM 校对。本轮没有新增 QEMU 拍摄、像素硬件模型、刷写或 Git 提交。原升级包、四个解包模块和四个既有模型源码保持原哈希，见校验结果（`analysis/raw-controls-2026-11-08/verification.json`，本地归档未公开）。

## 2. 静态照片对象中的生产与传递

记照片帧为 `frame`，其 `+3a4` 指向 `owner`。新曲线所在资源来自 `frame+270`；它与此前主 RAW 的 `frame+1f8` 句柄分别记录，避免把附属资源直接当作主像素缓冲。

`100ace06` 检查 `frame+270` 和 `frame+1b8`，在 `100ace68..100aceac` 装配输出地址，再调用 `100c29c6 → 101004c0 → 1017235a`。输出指针关系为：

| 输出 | 静态对象地址 | 长度／用途 |
| --- | --- | --- |
| 第一张曲线 | `*(frame+270)+994` | 257 个 u16，514 字节 |
| 混合强度后的曲线 | `*(frame+270)+b96` | 257 个 u16，514 字节 |
| 参数状态 | `owner+358` | 32 字节；部分路径也是输入缓存 |
| 记录区 | `*(owner+285c)` | 包含参数与状态的记录；实验显式提供私有输出空间 |
| 导出系数 | `owner+1014` | 四个 i32、一个 u16，位于 20 字节结构中 |

`100c289e` 从 `owner+25e` 经 `100c2aea` 写入生成器属性 `+52`；数值 0、1、2、3 由该转换保持不变。属性 `+62` 区分输入缓存路径；非缓存路径的 `+63` 来自 `owner+25f`。缓存路径复制 `owner+358` 的状态到计算上下文 `+2cc` 后执行。

另外，`101ba85a..101ba86a` 将另一个状态对象 `+1300` 的 20 字节复制到 `owner+1014`，`101baaa2..101baab2` 有反向复制。`100c1fba` 也通过同一生成器向该状态对象输出。由此明确这块数据有独立生产和复制路径；早期仅凭它位于 `owner+f58` 之后而猜测是主参数导出器直接填充，已被更具体的写入证据替代。

以上上层连接来自反汇编。隔离实验直接调用原厂生成器，并对接原厂下游函数；没有声称完整拍摄任务已经执行上述全部入口。

## 3. 原厂曲线和中性分支的实际结果

完整入口 `1017235a` 调用 `101a1066`。后者调用 `101a0f70` 选择生成路径，并形成两张曲线；`101a0a8a` 导出系数。

当计算上下文 `+2cc` 非零时，原厂函数 `101a1240` 将两张曲线的 **全部 257 项设为 1024**，并清零内部四项系数。导出函数也将四个 i32 和强度 u16 置零。本轮缓存／非缓存两条入口都到达这一中性分支。

为了检验有效数值传播，缓存的二项式分支使用人工参数 `a=256、b=4、截止索引=160`。在这一输入范围，原指令生成的第一张曲线与下面的数值计算逐项相等：

```text
j = min(i, 160), i = 0..256
T[i] = clamp(((4*j + 256)*j + 0x400000) >> 12, 1024, 65535)
```

第二张曲线由原厂混合强度 L 生成；本组非负、无溢出输入下，其结果逐项等于 `1024 - L + floor(T[i]*L/1024)`。这里的 i 是参数表索引，不擅自指定它与传感器半径或坐标的实际换算。

| 属性 +52 数值 | L | 第一张表取样 i=0/64/128/160 | 混合表取样 i=0/64/128/160 | 相对数值 0 改变的 MMIO 字数 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 1024/1032/1048/1059 | 1024/1024/1024/1024 | 0 |
| 1 | 68 | 同上 | 1024/1024/1025/1026 | 79 |
| 2 | 136 | 同上 | 1024/1025/1027/1028 | 97 |
| 3 | 204 | 同上 | 1024/1025/1028/1030 | 103 |

四种强度下导出系数均为 `[10240,25600,0,0]`，另行记录 L。还覆盖了四系数缓存分支，人工系数 `[4096,2048,1024,512]` 完整进入导出结构并产生另一条曲线。

数值 0 的混合表为中性，而导出系数仍可非零。对真实 NEF 的解读因此需要同时检查强度和使能，不能只看到非零系数便断言像素已被校正。这里的数值档位尚不命名为具体用户菜单项。

## 4. 同一条曲线确实进入独立的处理表区

静态照片的 `100ad7d8` 将第二张曲线指针交给 `100c2842 → 10171dbc → 1019b85e`。普通表生成分支中的 `1019bab4` 调用 `1019bf9a`，后者：

1. 读取上下文 `+8` 指向的曲线。
2. 每两个 u16 打包为一个 u32；最后一个 u16 独占最后一个字的低半部。
3. 写入表对象 `B+2a50` 或 `B+2c54`，并设置 `B+39e7` 或 `B+39e8` 上传标志。状态 `history+25a` 和属性 `+2c` 参与选择。

`100b3f94` 在 `100b40ea..100b4120` 把这两处地址放入处理包 `+48` 指向的双指针结构。完整配置驱动 `100d5c86` 调用 `10107a70 → 1010897c`，每张表上传 **129 个 u32，即 516 字节**：

| 逻辑表槽 | 表对象地址 | 硬件地址范围，末端包含 |
| --- | --- | --- |
| 0 | `B+2a50` | `bank+2890 .. bank+2a90` |
| 1 | `B+2c54` | `bank+2a94 .. bank+2c94` |

本轮动态验证的是 **bank 0、表槽 0**，`bank=20380000`。表槽 1 的选择关系为静态指令证据，尚未计为动态通过。每组记录的读取覆盖全部 257 个元素；读取 PC 为 `1019bffc/1019bffe/1019c010`，最后上传写入 PC 为 `10108992`。中间完整表缓冲、完整处理包和最终寄存器区均保存并逐字比较。

强度变化造成的全部配置差异均位于新表区；原四槽相关 `bank+700..738`、`0x720`、旧两组空间表 `bank+1200..1244` 保持一致。因此新曲线和旧两组 17 项表已有明确的数据与地址区分。这里的“MMIO 写入”指在 Unicorn 私有普通 RAM 中执行原厂驱动得到的写入轨迹，不是物理设备读回。

## 5. 另一个独立控制分支：参数不变，上传表变为中性

主参数生成函数 `101a0828` 检查 `properties+7d`：

| 属性 +7d | A+2b4 | 计算上下文 +604 | 导出属性 +6c |
| --- | --- | --- | --- |
| 本轮数值 0 | 1 | 0 | 0 |
| 本轮数值 2／3 | 0 | 1 | 1 |

`10171dfc` 中的 `10171f6c..10171f74` 完成最后一列的导出。`1019bf9a` 遇到该导出属性 `+6c` 非零时，直接打包常数 1024，跳过对已生成曲线的读取。驱动 `10107a0c` 又把 `A+2b4` 的低字节送入 `bank+9cc` 的最高字节。

三组对照均保留同一条非中性曲线、系数 `[10240,25600,0,0]`、强度 136。数值 2／3 与数值 0 相比，最终差异仅为 `bank+9cc` 和表区内 97 个字；**116 字节 NEFInfo 0006 完全相同**。这一对照把“记录什么参数”与“实际上传什么参数”明确分开。

该最高字节的物理使能语义、全局数值模式的摄影含义仍需进一步定位。`properties+7d` 可能还有其他消费者，本轮没有把全局模式 2／3 当作可用补丁。后续优先研究该支线自身的中性化与控制，而不是任意改变整机模式。

## 6. NEFInfo 0006 的完整导出

回调 `10289942` 调用 `101bb332(owner, payload+4)`，生成 116 字节载荷，并以种子 `ffff` 计算最后两字节 CRC16。原始版本指针由 `10305628` 初始化。每个有效用例都检查了版本、长度、输出指针推进、字段和值及 CRC。

| owner 字段 | 标签载荷偏移 | 内容 |
| --- | --- | --- |
| +1020 | +14 | 第四个 i32 |
| +101c | +24 | 第三个 i32 |
| +1018 | +34 | 第二个 i32 |
| +1014 | +44 | 第一个 i32 |
| +1024 | +60 | u16 扩展到 u32 的强度 |

标签 `+4` 状态字节由独立条件决定：`owner+22d6` 的 bit3 非零时为 0；否则 `owner+25e` 非零时为 1，为零时为 2。额外四组状态对照保持系数和曲线不变，只改变该状态字节及 CRC。这个事实不赋予状态 0/1/2 在真机像素处理上的新含义。

旧 NEFInfo 0007 仍使用 `owner+ff8..1013` 的另一套数据。本轮用保护字节检查其区域保持原值。0006 的有名称系数与 0007 的待定系数分别保存，避免混称为彩圈开关。

## 7. 实验环境、失败记录与复现

原 ROM 以只读／可执行权限映射到进程内。参数、缓存、历史、输出、标定和 MMIO 均使用明确的私有 RAM 夹具。图片地址 `60000000/62000000` 不映射，完整驱动调用的启动参数为 0；没有补传感器算法、像素校正算法、等待成功或拍摄完成事件。原始固件文件不写入。

使用 BLOCK、MEM_READ 钩子及限定于 MMIO 区的写钩子；避免已知会影响本机 Unicorn IT/memset 路径的普通 RAM 写钩子。每次执行前清理翻译缓存。数值、完整缓冲、调用轨迹和读写 PC 均保留。

第一次、第二次扩展到完整处理包时，在 `1011f10e` 读取标定表失败，分别保存于 `curve-packing-probe` 和 `isolated-curve-packing`。早期曾怀疑与整体启动数据和 OS 依赖有关；随后反汇编明确读地址来自 `c18fa954+14` 加标定偏移。补充与此前研究相同的私有零标定区域后完整运行通过，未替换函数返回值。前两次是夹具缺项，不计为固件故障或有效用例。

后续把直接输入的强度属性与 owner+25e 同步，保持原厂转换关系；追加状态基线用例，形成最终 15 组。此前 11／14 组运行是迭代记录，不累计成额外独立样本。最终完整明细见有效结果（`analysis/raw-controls-2026-11-08/validated-controls/result.json`，本地归档未公开），简表见证据摘要（`analysis/raw-controls-2026-11-08/evidence-summary.json`，本地归档未公开），全部命令目录（`analysis/raw-controls-2026-11-08/commands`，本地归档未公开）。

## 8. 下一步保持围绕最终目标

1. **确认新支线在实际天文配置中的状态与 RAW 取样位置。** 沿 `bank+9cc`、两张 257 项表和已有输入 `+310`／写回 `+3ec` 查硬件通路。同一请求需要有效输入、真实处理写回与编码输入。优先确认它是否在无电子镜头条件下已经中性；若已中性，就降低其作为硬编码彩圈根因的优先级。
2. **机身固定彩圈校正继续单独定位。** 对比新曲线的输入来源、旧两组 17 项表和逐机标定加载。Mark Shelley 对接望远镜仍有硬编码校正的观察保留为外部问题定义，见[原文](https://www.markshelley.co.uk/Astronomy/NikonConcentricRings/nikon_hardcoded_correction.html)与固定资料（`references/web/hardcoded_correction.html`，本地归档未公开）。本轮未重新调查网页更新，也没有将普通暗角曲线等同于该现象。
3. **暗电流线继续追真实运算与保存数据。** 保留 `0x3e1 → 前端正参数／四路负偏移／0x720／BlackLevel` 的既有证据，进一步查偏置、扣减、钳位和前后端位置。新暗角分支与它们可独立变化，有助于今后做单因素对照；本轮没有新增暗场像素验收。

研究已从候选名称推进到可执行的独立参数链和控制条件。下一阶段的决定性进展是将这些控制与**最终保存的 NEF 样本**对应起来，而不是继续以元数据、完成事件或零缓冲替代像素检验。
