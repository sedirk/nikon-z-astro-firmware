# RAW 输出、四槽控制与相邻参数

日期：2026-11-03，Asia/Shanghai。初代 Nikon Z6 C3.80。接续 [0x3e1 与 NEF 保存内容](RAW_NEF_INFLUENCE_2026-11-03.md)。目标仍是保留暗电流、关闭静态 NEF 写入前的 RAW 校正并消除彩圈。

同日后续：[候选处理与 NEF 像素证据](RAW_PIXEL_STAGE_2026-11-03.md)。新增完整配置包内的独立参数对照，找到空间表同源系数到 NEFInfo 0x0007 的写入链；实际像素影响仍未验证。本文保留本轮当时的参数、缓存和输出关系证据。

**本轮新增最直接的发现：0x3e1 对应的标定标量还参与计算 `bank+0x720` 的有上限参数。** 在已有的前端正数参数、后端四路负偏移、NEF BlackLevel 之外，又找到一个需要同时考虑的依赖；缓存分支还可以跳过它的重新计算。另已连接一条带坐标与两组 17 项表的参数路径到处理寄存器。

**仍未证明四路负偏移会改变最终保存的 RAW 像素，也没有暗电流保留、关闭校正或消圈成果。** 原厂代码能证明如何生成、选择、上传参数；尚缺硅片取样点、使能极性、实际像素运算和裁切顺序。`0x720` 的参数计算有上限，不等于已经证明它是像素裁切阈值。没有完整 NEF、真机内存或用户机身样本。

## 1. 新的标量依赖：四个相邻值与 0x720

为沿用前文，A 指主参数块（静态路径为 owner+0x394），context 指 `0x10171fae` 使用的参数生成上下文，properties 是 context+0 指向的输入。

四槽上传器 `0x10107262` 实际读取四组三个 u16，以及末尾另一个 u16：

| A 中字段 | 寄存器偏移 | 已确认的软件含义 |
| --- | --- | --- |
| +184、+18a、+190、+196 | +708、+70c | 四个增益形式的参数；尚未确定实际通道颜色 |
| +186、+18c、+192、+198 | +710、+714 | 标定标量取负，上传低 13 位 |
| +188、+18e、+194、+19a | +718、+71c | 另一路原厂表选择、插值产生的四个值 |
| +19c | +720 | 由标量、增益和上述四值计算，并在软件中限制最大值为 0x7fff |

普通 bank 基址为 `0x20380000 + bank_index*0x40000`。不能只看负偏移的两个寄存器就推导整个单元的运算。

新恢复的依赖：

```text
properties+0x86（前文已连接到 0x3e1 的标定查询）
  → 0x1019e656：写入 context+0xf8+0x26
  → 0x1019f10c 的末尾调用 0x1019e8b2
      0x1019e75c 选择 ROM 表与插值项
      写 context+0x4e/+0x50/+0x52/+0x54（四值 T）
      写 context+0x56（有上限参数 L）
  → 0x101965c0 → 0x10196060
      复制 T 到 A+188/+18e/+194/+19a，L 到 A+19c
  → 0x10107262 → bank+718/+71c/+720
```

对本轮非负输入，可把 L 的计算写成：

```text
B = properties+0x86 的标定标量
G = context+0x26 的增益参数
T0..T3 = 原厂表选择和插值结果
L = min(原厂 0x1015b894 取整除法(((16383-B)*G + 64*ΣT), 256), 32767)
```

该公式描述参数生成，**不是我们自行建立的像素算法**。没有假定像素执行 `(像素-B)*G+T`，没有确认硬件的有符号解释、运算先后、饱和或低端裁切。

六组隔离对照实际执行原厂配置查询、标量保存块、属性传递块、参数输入构造、ROM 选择与计算、存储块和寄存器上传。标定记录为人工的 300；选中的原始 ROM 记录地址为 `0x11634ed2`，本组 T 均为 300，ROM 没有修改。

| G | 0x3e1=0，B=300：L | 0x3e1=1，B=0：L |
| --- | ---: | ---: |
| 256 | 16383 | 16683 |
| 512 | 32466 | 32767 |
| 1024 | 32767 | 32767 |

四个 T 在这六组中都保持 300；负偏移则随 B 从四个 `0xfed4` 变为零。G=1024 时，软件上限掩盖了 L 的输入变化，所以“寄存器没变”也不能直接推断没有依赖。

**缓存限制：** `properties+0x7e != 0` 时，`0x10171fae` 从调用者的缓存复制 0x34 字节到 context+0x24，跳过 `0x1019f10c`，随后仍执行负偏移生成器 `0x1019f3d0`。两组原厂入口前缀对照用人工缓存 T=[111,222,333,444]、L=12345：B=300/0 会改变负偏移，但 L 继续为 12345。这不是相机当前默认缓存内容，也不能将前表结论推广到所有缓存状态。

## 2. RAW 输出请求与四槽不是同一个控制

这次完整执行了原厂处理包构造器 `0x100b5716`，然后将处理包缩减到与本问题相关的块，调用原厂驱动 `0x100d5c86`。驱动使用 r2=0，因此不执行硬件复位、启动和完成；处理模式 +0x374=0，分别覆盖 bank 0/1、有无替换输出，共四组。

| 请求 +0x1a8 | bank+3ec 输出地址 | bank+580 | bank+67c | bank+710/+714 |
| --- | --- | ---: | ---: | --- |
| 有替换输出 | 人工地址 0x62000000 | 1 | 0x300 | 均上传 0x1ed41ed4 |
| 空 | 地址寄存器不写，保留试验哨兵 | 0 | 0x100 | 均上传 0x1ed41ed4 |

该结果证明输出请求和负偏移上传在软件配置上可以分别变化；没有输出时仍上传负偏移，也再次说明“同包出现”不等于对同一输出起作用。地址不写不等于硬件复位为零。

另一组五位掩码 A+0x3e 经 `0x10106360` 写到 bank+120/+124/+128/+12c/+130。恢复的 core 构造器中，bit 0 取决于 +0x37c 相关辅助描述符，bit 1 取决于请求 +0x370，bit 2 清零，bit 3 取决于 +0x1c 或 +0x9c，bit 4 取决于 +0x9c。它不直接检查 +0x1a8。四组独立对照得到掩码 2、8、24、26；前面的 RAW 输出对照则五位均零。

因此暂不能把这五位命名为“全部 RAW 校正总开关”。目前也没有恢复一个能证明 RAW 从四槽前、还是四槽后取样的选择器。上一轮 bank=1、packet+0xcc 非零时跳过普通配置的特殊分支结论继续适用；本轮普通模式的结果不替代该条件。

## 3. 四槽附近控制位还有几何参数依赖

`0x1010722a` 对 A+0x17e 开始的五字节打包：

```text
bank+700 = (A[17e]<<8) | ((A[17f]&1)<<1) | (A[180]&1)
bank+704 = ((A[181]&1)<<1) | (A[182]&1)
```

`0x1019f3d0` 会把 A+17f、A+181 清零，但 A+17e、A+180、A+182 来自另一条路径。清两个字节不能直接解释为关闭整个单元；使能的有效电平仍未知。

core 构造器 `0x100b3b2c` 读取 A+181 和 A+17f，影响 A+1c..23 的八个边界／处理余量形式的字段，这些字段随后打包进核心寄存器。五组隔离用例示例：

| owner 数值类别 | A+17f / A+181 | A+1c..23 |
| --- | --- | --- |
| 0 | 0 / 0 | 9,17,2,2,0,0,3,1 |
| 0 | 1 / 0 | 6,14,0,2,0,0,3,0 |
| 3 | 0 / 0 | 6,12,2,2,9,3,3,0 |
| 3 | 0 / 1 | 5,10,1,2,7,3,3,0 |
| 3 | 1 / 1 | 2,7,0,2,4,3,3,0 |

控制字节是人为单独改变的，并非已知菜单设置。类别 3 按此前恢复的分配限制没有设置 RAW 替换输出。不能把这些几何字段理解为像素数值的黑位裁切；但它们说明修改附近控制位可能同时影响边界配置，必须继续追踪。

## 4. 带坐标、六个系数与两组 17 项表的独立路径

恢复并执行了以下原厂路径：

```text
0x10196fe4（整理输入）→ 0x10197500
  → 0x10197820（标志选择）
  → 0x10197410（缓存、原厂表计算或零表分支）
  → 0x1019702a / 0x101973d4
→ 0x101975be
  控制字节 → A+17e/+180/+182
  坐标和尺寸形式字段 → A+1a2..1b0
  两组 17 个半字 → context+d8 指向的 68 字节块
→ 0x10198640..0x101986c6
  打包为 B+2578 与 B+259c 两块，每块 36 字节
  置 B+39a9/+39aa = 1
→ 0x100b3f94 → packet+38 的双指针
→ 0x100d5c86 → 0x1010737e → 0x1010897c
→ bank+1200..1220 与 bank+1224..1244
```

每个 17 半字块为 34 字节，原厂打包器补齐末尾高 16 位为零，按 9 个 u32 上传。B 是请求 +0x360 指向的表区。静态上游 `0x100ad6a2..6f2` 将 stage+0x4e8 交给参数生成器；`0x100ad7d8` 再把同一块和 stage+0x588 交给 `0x100c2842 → 0x10171dbc`，连接到上述打包器。没有把两个恰好相同的偏移当成同一对象。

`0x10197820` 的选择包含 properties+2c、properties+45 的 bit 2、context+33 及原始 ROM 表 `0x115cd67d`。这个 19 字节表只有数值索引 7、18 为零；尚未给索引赋予菜单或拍摄模式名称。另一缓存选择器 properties+96 会改用缓存标志和六个系数，和上一节 properties+7e 不同。

四组完整的本支线隔离对照覆盖普通零表、排除位、排除索引、缓存非零系数。缓存系数为人工 `[256,1048576,262144,-512,-524288,131072]`；两组表由原厂 `0x1019702a` 计算，没有自己实现一个替代算法。两组表经原厂打包、指针选择和 bank 1 驱动上传，72 字节全部匹配。改变这组控制时，四路负偏移仍为 0x1ed4，RAW 输出配置仍指向 0x62000000。

另一原厂函数 `0x10197678` 将六个系数及标志写到 context+e4 指向的结构；该静态调用映射到 owner+0xff8。后续输出消费者尚未定名。**本轮没有把它认定为 NEF 彩圈校正、镜头暗角、色差或硬编码颜色阴影。** 这是需要继续定位物理含义和 RAW 影响的空间参数候选；两条 17 项序列本身也不是一张已确认的二维空间增益图。
